## Goal

Replace the phase_1 placeholder state (DATABASE_URL is only an `.env.example`
line; no settings, no engine, no Alembic runtime wiring) with the database
foundation every later issue needs: a Pydantic Settings object reading the
Chapter 3 §3.10 variables, a SQLAlchemy 2.0 engine + session factory with the
SQLite PRAGMA handling, a working Alembic setup (`alembic upgrade head` runs
against `sqlite:///./dev.db` by default), and the t4 `make migrate` stub wired
to the real command. This is the database half of `docs/plan.md` § phase_2_auth
template 1, split off so t6 can land the User model on a clean migration chain.

## Acceptance criteria

- [ ] ac1 — `backend/app/config.py` defines a Pydantic 2 `Settings` class exposing at least `DATABASE_URL`, `DB_CONNECT_TIMEOUT`, `JWT_SECRET`, `JWT_ALGORITHM`, `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`, `JWT_ISSUER`, `JWT_AUDIENCE`, `CORS_ORIGINS`, `ENVIRONMENT`, `APP_VERSION` with defaults matching `.env.example`, loaded with priority env var > `.env` file > default (REQ-ARCH-061), and a module-level cached accessor using `@lru_cache` (REQ-BE-010/011). A unit test asserts an env-var override wins over the default value.
- [ ] ac2 — `Settings` enforces REQ-BE-012: when `ENVIRONMENT == "production"`, construction fails (validation error, not silent fallback) if `JWT_SECRET` is empty or the placeholder `"change-me"`; in development it is allowed. Unit test covers both branches.
- [ ] ac3 — `backend/app/database.py` provides `create_db_engine(...)` and a session factory with `get_db()` yielding a `Session` per request and closing it in a `finally` block (REQ-BE-040/REQ-ARCH-022). For SQLite URLs the engine connects with `check_same_thread=False` and executes `PRAGMA foreign_keys=ON` on every connect via `event.listens_for` (REQ-TECH-032). Integration test asserts `PRAGMA foreign_keys` returns 1 on a session from the factory.
- [ ] ac4 — Alembic is wired: `backend/alembic.ini` + `backend/alembic/env.py` exist (replacing the empty `backend/alembic/versions/.gitkeep`-only tree), `env.py` reads `DATABASE_URL` from the app settings (no hardcoded URL), and from `backend/` `uv run alembic upgrade head` exits 0 against the default SQLite URL with zero revisions. A placeholder-first migration chain is NOT required (t6 adds revision 001); this AC proves the harness runs.
- [ ] ac5 — The root `Makefile` `migrate` target is a real recipe (no longer an echo-only stub) that runs `uv run alembic upgrade head` in `backend/`; `make -n migrate` exits 0 and the recipe line is tab-indented and contains `alembic upgrade head`. (REQ-DOC-051 completion of the t4 forward-delegation.)
- [ ] ac6 — No regression: from `backend/`, `uv run pytest` exits 0 with the pre-existing tests (t1 smoke + t3 health) still passing, `uv run ruff check .` exits 0, and `uv run mypy .` (strict) exits 0. New code has complete type annotations and no `except Exception`.
