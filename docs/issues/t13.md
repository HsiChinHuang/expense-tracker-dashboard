## Goal

Deliver the complete expenses backend vertical: `Expense` model + Alembic
revision `004` (constraints + four indexes), Pydantic schemas with Decimal
amounts transmitted as strings, `expense_service` (create/list/get/update/
delete + the REQ-BE-075 serialization helper), the five endpoints under
`/api/v1/expenses`, and the audit integration — every create/update/delete
writes its audit row through t12's helper in the SAME session/commit as the
business write, and every write path validates the category through t11's
`validate_category_access`. This is the contract t16/t17 consume and t15
isolates.

## Acceptance criteria

- [ ] ac1 — Alembic revision `004_*` (down_revision `003`) creates `expenses` with REQ-DB-030 columns, both REQ-DB-031 CHECKs, REQ-DB-032 FK semantics (user CASCADE, category RESTRICT), and all four REQ-DB-033 indexes; upgrade/downgrade/upgrade runs cleanly on fresh SQLite; amount round-trips as `Decimal` with exact 2-dp equality through the ORM on SQLite (REQ-DB-090/091).
- [ ] ac2 — `POST /api/v1/expenses` valid body → 201 with the expense serialized per REQ-BE-075: `amount` as a 2-decimal STRING, `date` as `YYYY-MM-DD`, no raw float anywhere (REQ-SEC-050); invalid bodies → 422 `{detail, code, field}` for amount ≤ 0, amount with > 2 decimals, amount > 9,999,999,999.99, missing amount, invalid date, note > 500 chars, currency ≠ USD (REQ-PROD-031); category_id unknown, another user's, or otherwise inaccessible → 404 via t11's validator (REQ-API-041, REQ-SEC-032).
- [ ] ac3 — `GET /api/v1/expenses` returns a paginated envelope scoped to the caller (REQ-SEC-030) supporting `year_month`, `category_id`, `page`, `page_size` (default page_size 20 per REQ-PROJ-008); filters combine; invalid pagination (page < 1, page_size > 100 or < 1) → 422; empty result → empty list, 200 (REQ-API-040, REQ-PROD-031). `GET /api/v1/expenses/{id}` returns 200 for own rows and 404 for unknown AND other-user rows (REQ-API-042, REQ-SEC-031).
- [ ] ac4 — `PUT /api/v1/expenses/{id}` → 200 with full replacement validation incl. category re-validation; 404 for other-user/unknown; 422 for invalid bodies (REQ-API-043). `DELETE /api/v1/expenses/{id}` → 204 own; 404 other-user/unknown (REQ-API-044). Cross-user PUT/DELETE never leak existence (identical 404 body).
- [ ] ac5 — Audit integration (REQ-PROD-015/021, REQ-ARCH-078): create → audit CREATE (old_value NULL, new_value = serialized expense); update → UPDATE with both values; delete → DELETE with new_value NULL; all in the same transaction — a test forces audit failure and asserts the expense write rolled back. `GET /openapi.json` still lists no audit path.
- [ ] ac6 — No regression and quality gates: full `uv run pytest` green (merged + new expense nodes), `ruff check .`, strict `mypy .` exit 0; `/openapi.json` lists all five expense paths after health/auth/categories; revision chain single head `004`.
