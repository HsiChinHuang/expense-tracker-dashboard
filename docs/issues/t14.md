## Goal

Deliver the budgets backend vertical: `Budget` model + Alembic revision `005`
(unique per user/month + both CHECKs), `budget_service` (upsert get-or-zero
delete with `year_month` validation), and the three endpoints under
`/api/v1/budgets/{year_month}`. Budgets use the upsert semantics of FR-BUD-1:
`PUT` creates or replaces, `GET` on an absent month is NOT a 404 but a 200
with `amount "0.00"`, and `DELETE` on an absent month IS a 404. Audit rows are
written through t12's helper in the same transaction as the budget write, and
deleting a budget leaves expenses untouched (REQ-DB-042).

## Acceptance criteria

- [ ] ac1 — Alembic revision `005_*` (down_revision `004`) creates `budgets` with REQ-DB-040 columns, `UNIQUE(user_id, year_month)`, `CHECK amount > 0`, and the `year_month` format CHECK; upgrade/downgrade/upgrade clean on fresh SQLite; a test asserts a second concurrent-shaped insert for the same (user, month) raises IntegrityError (REQ-DB-041, REQ-PROD-032 duplicate-budget case).
- [ ] ac2 — `PUT /api/v1/budgets/{year_month}` with a valid body creates (200, new row) and, on second call for the same month, REPLACES the amount (200, single row — upsert, no duplicate) (REQ-API-051, REQ-BE-080, REQ-DB-042). Amount serializes as a 2-decimal string, never a float (REQ-SEC-050). Invalid `year_month` path forms (`2026-1`, `2026-13`, `2026-1-01`, `abcd-ef`) → 422/404 per Chapter 7 §7.6.2 — groom pins the exact status before implementation; negative or zero amount → 422 with `field="amount"` (REQ-BE-083, REQ-PROD-032).
- [ ] ac3 — `GET /api/v1/budgets/{year_month}` returns 200 with the stored budget for the caller, and 200 with `amount == "0.00"` (string) when no budget exists for that month — never a 404 for absence (REQ-API-050, REQ-BE-081, REQ-PROD-032 absent-budget case). A budget belonging to another user is not returned (REQ-SEC-030/031).
- [ ] ac4 — `DELETE /api/v1/budgets/{year_month}` returns 204 for an existing own budget and 404 when absent or owned by another user (REQ-API-052, REQ-PROD-032 delete-nonexistent case); deleting a budget leaves that month's expenses fully intact and queryable (REQ-DB-042).
- [ ] ac5 — Audit integration: budget create → audit CREATE (`entity_type == "budget"`, old NULL); update → UPDATE with both values; delete → DELETE (new NULL); same-transaction rollback test as t13 ac5 (REQ-PROD-015/021, REQ-ARCH-078, REQ-DB-051 entity_type CHECK coverage for 'budget').
