## Context

t57 landed `backend/scripts/req_coverage_verification.py` and its generated
artifact `docs/criteria/req_coverage_verification.md`. That generator is a
fail-closed fence: it exits nonzero IFF a GAP row or an unpointed non-GAP row
exists. At base commit 398c95b94d64089cfaea632f503fb77590d2b49d the matrix
enumerates 749 unique ids and classifies them IMPLEMENTED_TESTED 110,
IMPLEMENTED_STRUCTURAL 526, DEFERRED_RULLED 13, GAP 99, EXAMPLE_REFERENCE 1, so
the fence is RED by design. t57 shipped green precisely because the card expected
those GAP rows; closing them is this card's work. The instrument itself is not
the subject of t58 and must not be weakened.

then doc-hit, then code-source) means no in-repo file names the id at all. That
makes the closure mechanism uniform: authoring documentation that names the id
produces a doc-hit citation and the row leaves GAP. 97 of the 99 close that way.

rows MUST carry a non-empty `deferral_key=` field, because the generator emits
