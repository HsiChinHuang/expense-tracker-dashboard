# t60 - Nest /expenses /budgets /categories under the AppShell route so the shell survives navigation, add the Expenses nav entry and a NotFound route, and re-mark the shell requirement rows

## Context

**Issue:** #66 (milestone `phase_10_operator_ux`) — platform body is the placeholder "TBD by definer"; this card IS the specification.

**Files touched by this card** (4 paths, all owned; nothing else may change):
- `frontend/src/app.tsx` — modify: re-nest three routes, add one catch-all route, add one import
- `frontend/src/components/layout/app_shell.tsx` — modify: add one `NavLink` entry to the existing header nav
- `frontend/src/pages/not_found_page.tsx` — **new**: the 404 page
- `frontend/src/app_routing.test.tsx` — **new**: the shell-on-every-page proof test

**The defect.** `frontend/src/app.tsx` renders two route blocks: a `PublicOnlyRoute` block holding `/login` and `/register`, and a `ProtectedRoute` block holding `<Route path="/" element={<AppShell />}>` whose only child is `<Route index element={<DashboardPage />} />`. The three feature pages hang **off the same level as that shell block**, each in its own `<Route>` under `ProtectedRoute`:

```
<Route element={<ProtectedRoute />}>
  <Route path="/" element={<AppShell />}>   <- the shell wraps ONLY the index route
    <Route index element={<DashboardPage />} />
  </Route>
  <Route path="/expenses"   element={<ExpensesPage />} />    <- NO shell
  <Route path="/budgets"    element={<BudgetPage />} />      <- NO shell
  <Route path="/categories" element={<CategoriesPage />} />  <- NO shell
</Route>
```

`app_shell.tsx` renders its own header (brand + nav + `<Outlet />`), and the nav is built from the module-local `NavLink` guard-wrapper. So on `/dashboard`-equivalent (the index route) the user sees the header, brand and nav; the moment they land on `/expenses`, `/budgets` or `/categories` the header is **gone**, because those routes are siblings of the shell, not children of it. The pages are reachable only by typing the URL, since the nav links that would take you there are not rendered on the page you are on. This is the "shell disappears on navigation" defect.

**The 404 gap.** There is no catch-all route. An unknown path under the protected tree renders nothing at all (no shell, no page, no message).

**The nav gap.** `app_shell.tsx` renders exactly three `NavLink`s (`Dashboard` → `/`, `Budget` → `/budgets`, `Categories` → `/categories`). There is no route to the expenses list from the header.
