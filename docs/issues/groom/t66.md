## Context

This is the first README card of `phase_11_readme_demo_seed` (platform issue #72, `depends: [t65]`,
t65 merged at the base commit). It is the only card in the milestone that DELETES README content, so
it runs first and every later README card (t67 onward) writes into the slimmed file it produces.

**Measured base state (re-measured at 5e18a2a, not assumed).** `README.md` is 367 lines, pure ASCII,
CRLF working bytes (367 CR / 367 LF), cr-stripped sha256 `f0fd9eda96a242e4efdb378b2ad4fdc40458d05cd1395ad7088bf21f129995d8`.

reported by ac5.

**The problem this card had to design around, and its resolution (the W3 ruling).** The DEFINED draft
says the content is relocated AND that the command tokens must stay greppable in `README.md`. Those
two statements look contradictory until you read the carried gates. `tests[128]` (issue t24) greps

`Development versus production` headings, for the `make setup` / `make dev-backend` / `make dev-frontend`

(t49 ac4) reads `README.md` with `sed` ranges bounded by top-level headings and needs the criteria-mapping,
evidence-checklist, live-verification and local-verification sections to still exist with their rows.
`tests[119]` (t23) greps `README.md` for the six dashboard endpoint paths. So relocation cannot mean
removal for those tokens, and the card resolves it as an explicit **compatibility surface**: the prose,
rationale and detail move out to the three new documents, while `README.md` keeps a compact command and

ac6 fences it the only way that is actually checkable: by regenerating the matrix and requiring it to be
