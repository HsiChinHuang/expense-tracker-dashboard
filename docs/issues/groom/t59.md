Why this needs a different fence shape from t57 and t58. Those were single-gate cards: each proved
one slice and each fence was RED at base for the reason the card set out to fix. An exit composite
is the dual - it must attest a **conjunction** that is already true, which means most of its fences
are GREEN at base by construction. A green-at-base fence is exactly where a false attestation hides,
so every such fence here is required to carry a **seeded negative control** that fires inside the
same run: a seeded-GAP matrix, a wrong fixture token, a seeded unused-import file, a mutated pinned
digest, a one-character-tampered index copy, a planted full-form-id file, and a synthetic
non-docs delta. Each control is asserted to make the fence's own checker fail; a control that does
not fire turns the fence RED rather than passing silently.

The attestation-instrument problem. This card's deliverable *is* an attestation, so it is written to
the groom handoff and not to a new docs artifact - creating one would add a scanned file to the very
matrix it is attesting. The card itself still moves at merge: closure archives it into
`docs/issues/closed/`, which the generator scans as a citation source
(`backend/scripts/req_coverage_verification.py`, `SRC_DIRS`). A card that named any requirement id in
full form would therefore self-cite, move that row's pointer set under the committed report, and
break the byte-identity attestation the moment it merged. The card accordingly contains **zero**
full-form id tokens; ids are referenced only by family and count, or in the two-column
`REQ-FAMILY | NNN` shape the generator regex cannot match. ac6 proves this physically rather than by
inspection: it stages a byte copy of the card inside the scanned tree, regenerates the matrix to a
scratch output, byte-compares it against the committed report, and then plants a full-form id to
prove the scan is live.

Measured, not asserted. The platform draft carried four "accepted residuals" to be re-listed. Two of
them do not reproduce at this base and are recorded as **measured corrections** rather than repeated
as claims: the stale-README-wording residual is absent because the counted tokens are not present in
the pin-2 bytes, and the t49/t50 truncated-`ac_hash` residual is absent because all seven stored
digests in `merge_history.json` are full-length. The third (legacy zero values in the closed-card
index's tests column) does reproduce and is counted, not hand-waved: 53 rows. ac5 measures all three
on every run, so a residual that later becomes real fails loudly instead of staying accepted.

Environment prerequisites, because two of these fences are prerequisite-gated and the gate is
disclosed rather than hidden. The backend legs need the `uv` environment (`~/.local/bin` on the
executor PATH). The frontend legs need `frontend/node_modules` (`npm.cmd ci`); where it is absent the
fence prints an explicit prerequisite line instead of silently skipping, per the t42/t49 precedent.
An untracked `.env` in the working tree changes the matrix digest, because the generator hashes
scanned files and `.env` is scanned; every fence that byte-compares the matrix therefore moves the
file aside under the WAL 719 clean-tree protocol and restores it by `trap`. All git metadata reads go
through `cmd.exe /c "git -C <win-path> ..."`, and no fence touches the network or a container.

  its five-label vocabulary, its fail-closed exit contract, its fixture self-test, or any floor value
  in this card. Floors are measured at base and pinned upward; they are never lowered here.

  stands; resolving a deferral is a separate card with its own ruling.

  are asserted, and pin-3 is forbidden.
