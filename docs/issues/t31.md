## Goal

Land the MCP server core in a NEW top-level `mcp-server/` workspace:
`config.py` (env-driven settings + the JWT algorithm/issuer/audience
constants), `auth.py` (`verify_jwt` + `get_user_token`), and `server.py`
(the stdio JSON-RPC loop: `list_tools` returning exactly four tool
definitions with strict schemas, `call_tool` verifying JWT first and then
dispatching to `tools/<name>.py` modules), plus a COPY-ONLY
`mcp-server/pyproject.toml` that declares the project for REQ-TECH-026's
verification pointer and for CI's own isolated install. The `mcp` SDK is
deliberately NOT a dependency: it is not installable on this host (measured
at survey — `uv` cannot resolve ANY package without egress), so the server
speaks the MCP wire protocol directly over stdio (newline-delimited JSON-RPC
2.0: `initialize` / `tools/list` / `tools/call`), which is also what makes
the module importable and testable hermetically in t32. Zero dependency
installation is performed by any card on this host (survey ruling 3); the
manifest exists so a network-equipped runner can resolve it.

- [ ] ac1 — `mcp-server/` contains exactly the REQ-AI-081 core at this stage: `config.py`, `auth.py`, `server.py`, `pyproject.toml` (tools/, `__init__.py`, tests and README land in t32) — and `config.py` reads `MCP_JWT_SECRET`, `MCP_API_BASE_URL`, `MCP_USER_TOKEN` from the environment and defines the JWT algorithm (`HS256`), issuer (`expense-tracker`) and audience (`expense-tracker-api`) EXACTLY as the merged backend does (the values present in `.env.example` / `backend/app/config.py`), so an agent token minted by the backend verifies at the MCP layer (REQ-EXT-032, REQ-AI-086 env triple).
- [ ] ac2 — `auth.py` defines `verify_jwt(token: str) -> str` validating signature, expiry, audience, issuer and `type == "access"` and returning `sub`, and `get_user_token() -> str` reading `MCP_USER_TOKEN`; it uses the ALREADY-INSTALLED `python-jose` (`from jose import jwt, JWTError`) and raises a specific `AuthError` subclassing `Exception` on every failure — never a bare `except Exception` swallow (REQ-AI-083, REQ-EXT-033).
- [ ] ac3 — `server.py` implements the stdio MCP contract hermetically: `list_tools()` returns EXACTLY the four definitions `add_expense`, `get_budget_status`, `monthly_summary`, `list_expenses` with strict JSON-schema `inputSchema` objects (typed properties, `required` lists, `additionalProperties: false`), and `call_tool(name, arguments)` verifies the JWT BEFORE any dispatch and then routes to the matching `tools/<name>.py` module; the loop is newline-delimited JSON-RPC 2.0 over stdio with `initialize` / `tools/list` / `tools/call` handling and a JSON-RPC error object on failure (REQ-AI-082, REQ-AI-085, REQ-EXT-031, REQ-EXT-038, REQ-EXT-081).
