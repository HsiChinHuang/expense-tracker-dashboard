## Goal

Make `make security-semgrep` (and therefore the `make security` umbrella) executable on the current pinned toolchain. Root cause (t38-groom-measured): semgrep 1.180.0 refuses `--config auto` combined with the explicit CLI flag `--metrics off` ("Cannot create auto config when metrics are off"); Makefile line 123 passes exactly that flag, so the target exits rc=2 deterministically in ~6s without producing a report. No environment override (SEMGREP_SEND_METRICS=off included) rescues an explicit CLI flag. Without the flag the identical command succeeds (measured rc=0, 69s cold / 84s warm, valid {version,results,errors} JSON).

## Measured evidence (pinned)

1. `SEMGREP_REPORT=<tmp> make security-semgrep` at MAIN 6873ca1: rc=2 in 6s, stderr contains "Cannot create auto config when metrics are off" (t38 groom handoff blocker row).
2. `uvx semgrep --config auto --json --quiet --timeout 60 --output <tmp> .` (same command minus `--metrics off`): rc=0, 32 findings, keys version/results/errors (t38 groom handoff).
3. t36 stored gate tests[159] runs `make -n security-*` and greps each target names its report path - it does NOT pin the `--metrics off` flag text, so removing the flag keeps tests[159] green (orchestrator-verified against docs/state/merge_test_index.json tests[159], WAL 542).
