## Goal

Create the monorepo directory skeleton matching the Chapter 16 tree so all
later issues have a fixed home for their files. Only directories, placeholder
`__init__.py` / `.gitkeep` markers, and an extension of the existing
`.gitignore` — no application code.

- [ ] ac2: `backend/` layering per REQ-STRUCT-012 exists: `backend/app/__init__.py` plus subpackages `models/`, `schemas/`, `routers/`, `services/`, `auth/`, `audit/`, `core/`, `scripts/` each containing an (empty) `__init__.py`; `backend/tests/__init__.py`, `backend/tests/unit/__init__.py`, `backend/tests/integration/__init__.py`; and `backend/alembic/versions/` with a `.gitkeep`. No other files under `backend/`. (REQ-STRUCT-012.)
- [ ] ac3: `frontend/` layering per REQ-STRUCT-011 exists: each of `frontend/src/api/`, `frontend/src/components/ui/`, `frontend/src/components/layout/`, `frontend/src/components/charts/`, `frontend/src/components/forms/`, `frontend/src/components/common/`, `frontend/src/pages/`, `frontend/src/hooks/`, `frontend/src/context/`, `frontend/src/types/`, `frontend/src/utils/`, `frontend/src/test/`, and `frontend/public/` contains a `.gitkeep` and nothing else. (REQ-STRUCT-011.)

- [ ] ac6: Skeleton is placeholder-only: every file created under `frontend/`, `backend/`, `e2e/`, `security/`, `ops/`, and `.github/` is either `.gitkeep` or an empty `__init__.py`; no `.py` file other than `__init__.py` exists under `backend/`, and no `.ts`/`.tsx` file exists under `frontend/`. (No application code in this issue.)

This is the first issue of milestone phase_1_init (docs/plan.md). Later issues
t1 (backend skeleton, platform #4), t2 (frontend skeleton, platform #5),
t3 (health endpoint, platform #6) and t4 (root config files, platform #7) all
depend on a fixed home for their files, so the Chapter 16 directory tree
(requirements/Chapter16_ProjectStructure.md §16.1) and the directory
responsibility tables (§16.2.1–16.2.3) are materialized here as placeholders.

Important repo reality (review_plan warning, resolved in this groom): this is
NOT a greenfield repo. The agent-workflow tooling baseline is already tracked:
`.gitignore` (comprehensive), `.env.example`, `README.md`, `docs/`,
`AGENTS.md`, `launcher/`, `scripts/`, `skills/`, `schemas/`. Therefore:
"docs/ exists" is already satisfied and drives no change, and the `.gitignore`
AC is phrased as "extend the existing tracked .gitignore" with only the
REQ-STRUCT-060 entries still missing today (`*.db`, `*.sqlite3`,
`RENDER_DEPLOY_HOOK`, generic `*.log`, plus `build/` and `coverage/`).

Granularity note: t0 exceeds `limits.issue_granularity.max_files = 4` by
design (`warn_only = true`); splitting a placeholder-only skeleton would add
dependency overhead for no risk reduction. Do not inflate the scope further.
