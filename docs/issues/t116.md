## Goal

Part 1 of the README is the product's front door, fixed by t111. Part 2 is the
reviewer's coordinate system: one level-2 section, twelve rows - one per grading
dimension - each giving the maximum, this project's claim, a one-line reason, **one**
30-second first entry point, and where to go deeper. It has to be readable by a human
grader in a minute and parseable by an AI grading agent without any inference.

This card is an **assembly** card. It invents nothing: every claim it writes is lifted
from a t112-t115 record that measured it, and where those records claim below the
maximum - Observability's missing trace-ID correlation, On-Call Agent's human-operates
boundary, CI/CD's missing second environment - Part 2 says the same thing in the same
words. The one dimension that is not a full mark by default is CI/CD, which claims
**2/3** with the gap priced.

Two mechanical facts make this card the riskiest of the phase, and both are handled by
measurement rather than optimism: adding a level-2 section breaks a stored gate that
asserts seventeen headings, and adding 30-90 lines breaks a stored gate that asserts a
400-line ceiling. This card therefore measures the line count **before** it finalizes,
proposes the two band amendments in writing, and refuses to invent its own fallback.

**Honesty rule (binding on every cell):** each row's claim must be checkable within 30
seconds at the row's own First entry point. A row that claims more than its cited record
claims is a FAIL, and a row whose entry point does not exist on the merged tree is a
