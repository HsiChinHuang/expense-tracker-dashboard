## Goal

Creating a category must not require guessing the colour format. The operator's
attempts all failed on an unhelpful 422 because the field shows no example and
no format, while the backend demands `#` plus exactly six hex digits.

## Measured base state (re-measured at survey, not assumed)

- `frontend/src/components/forms/category_form.tsx` lines 71-88: a `Color` label
  and a bare `<input>` with NO placeholder, NO example, NO type, and a
  client-side leg that is only `frontend/src/utils/validation.ts:124-126`
  `color: z.string().regex(/^#[0-9A-Fa-f]{6}$/, 'Color must be a 6-digit HEX value')`.
  The `Icon (optional)` label carries no example either.
- The authoritative format, quoted FROM the file (not from memory):
  `backend/app/schemas/category.py` line 24
  `HEX_COLOR_PATTERN = r"^#[0-9A-Fa-f]{6}$"`
  applied at line 47 `color: str = Field(pattern=HEX_COLOR_PATTERN)`.
  The database enforces the same shape again:
  `backend/app/models/category.py` line 30-33 `COLOR_CHECK_SQL = ("length(color) = 7 AND substr(color, 1, 1) = '#' AND rtrim(upper(substr(color, 2)), '0123456789ABCDEF') = ''")`
  registered at line 55 as `ck_categories_color_format` (same constraint in
  `backend/alembic/versions/002_categories.py:60`).
- Failure mode today: a non-conforming colour leaves the client leg showing a
  terse message and, if it somehow passes, the API answers 422 and the page
  surfaces it through `applyApiErrors` / the toast - which is exactly the dead
  end the operator hit.
- What the colour is FOR (this must be stated in the card so the fix is
  judged against the right purpose): per-category chart colours.
  `frontend/src/components/charts/category_pie_chart.tsx` line 83 renders
  `fill: row.color ?? FALLBACK_SLICE_COLOR`, i.e. the stored hex goes verbatim
  into the pie slice fill, and `category_pie_chart.test.tsx` asserts the slices
  carry the API colours.
- Pinned call-site that MUST be dispositioned explicitly:
  `frontend/src/pages/categories_page.test.tsx:83-90` - `fillCreateForm` does
  `fireEvent.change(screen.getByLabelText('Color'), ...)` and line 185/215 call
  it with `'#123456'`; the payload assertion at line 193 expects
  `payload.color === '#123456'`. Adding a second colour control makes
  `getByLabelText('Color')` ambiguous, so the label/accessible-name choice is a
  card decision that must be recorded, not discovered by the builder.

## AC draft (groom will fence these)

- **ac1 - the colour control.** The form renders a native `<input type="color">`
  AND a text field whose `placeholder` shows the `#RRGGBB` example, with a live
  swatch preview that reflects the current value. The two controls stay in sync
  (picker -> text, text -> picker when the text is valid). Accessible names must
  keep `getByLabelText` unambiguous for the existing page test family.
- **ac2 - a sensible default.** The colour field is prefilled with the fixed
  neutral `#6B7280` (operator-accepted fixed value, not a random generator), and
  resetting the form after a successful create returns to that default.
- **ac3 - client-side validation quoted from the schema.** The client regex is
  byte-identical to `HEX_COLOR_PATTERN` as quoted above, and the card proves the
  identity by extracting the pattern FROM `backend/app/schemas/category.py` at
  verification time and comparing it to the pattern string in the frontend
  source - not by restating it from memory. A human-readable error message
  names the expected shape. The AC also states plainly that frontend validation
  is ADVISORY and the backend schema plus `ck_categories_color_format` remain
  the final gate.
- **ac4 - the icon hint.** The icon field carries a hint of the form
  `(optional, e.g. utensils)` while keeping the existing behaviour that an empty
  icon OMITS the `icon` key from the payload (the merged Q7 contract, asserted by
  `categories_page.test.tsx`).
- **ac5 - pin disposition and purpose statement.** The `Color` label pins above
  are dispositioned with old assertion, new assertion and reason; the card
  records the measured command it ran (`npx vitest run` over the touched files
  from `frontend/`) and states the colour's purpose (chart colours) so a
  reviewer can judge the picker choice.
- **ac6 - delta purity.** Backend, API, `openapi.yaml`, database, migrations,
  seed data, README and `docs/` are byte-unchanged; the payload shape stays
  `{name, color, icon?}`.
