## Goal

Produce the one artifact the whole milestone has been missing: a recorded,
checkable, NON-FABRICATED capture of a real green deploy. t26 shipped the
mechanism and documented that its final step had never run green; the operator
has since pushed and the service is live, so the run exists and can be read
back from the platform. This card's entire value is that the numbers in it are
measured from the platform, not authored by the builder. The record then becomes
the citation surface for t93, t98, t94 and t95.

## Constraints

- A fabricated, guessed, reused-from-history, or placeholder `workflow_run` id is
  a FAIL, not a defect. So is a run id copied from an earlier milestone (the
  `38336119379` line in the index is precedent for the SHAPE of a citation, not
  a value this card may use).
- No log line may be reconstructed from knowledge of the code. If the log cannot
  be retrieved, the card is BLOCKED and says so; it does not paraphrase.
- The card writes no product file, edits no gate, closes no issue, and does not
  touch `ops/**` or `docs/criteria/**` (t93/t98 consume this record; they own
  those surfaces).
- Rate discipline: platform reads go through `scripts/platform.ts` at max 5
  requests/second, one logical operation per `cmd.exe /d /c` call.
- ASSUMPTION (groom must verify): that the deploy-job log of a green run
  contains that exact string, which survey did not measure because no green
  post-t90 run existed at survey time. If the real log wording differs, groom
  pins the REAL string, records the difference as a premise correction in
  Context, and does not quietly weaken the assertion.
