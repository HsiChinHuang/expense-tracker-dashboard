## Goal

Make the live E2E workflow reach conclusion success on a main push. Root cause (orchestrator-measured on MAIN after the t42 merge): the compose stack sets DATABASE_URL=postgresql+psycopg://... but NEITHER backend/pyproject.toml NOR backend/uv.lock contains psycopg ANYWHERE (grep count 0/0). SQLAlchemy resolves the +psycopg dialect lazily; at container start the CMD runs uv run alembic upgrade head which raises ModuleNotFoundError: No module named 'psycopg'; the app container exits; port 8000 never listens; the E2E wait step logs curl (56) Recv failure then curl (7) connection refused x29 and fails. The E2E workflow has NEVER succeeded (71 failures + 1 cancelled, zero success, all history).
