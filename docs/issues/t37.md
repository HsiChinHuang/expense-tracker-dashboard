## Goal

the t36 pipeline against the merged tree: `security/gitleaks-report.json`
(gitleaks v8.30.1, tracked-tree sweep, zero-leak proven),
`security/pip-audit-report.txt` (`uv export --no-hashes --frozen` of
`backend/uv.lock` -> `uvx pip-audit -r`; the measured run found 3 known
vulnerabilities in 2 packages — recorded, never suppressed), and
`security/npm-audit-report.txt` (`npm audit` via cmd.exe against
`frontend/`; measured runnable, npm audit 9.2.0). Each report is the tool's

for the python leg, npm audit's real output for the JS leg — preceded only by
what the tool itself emits; provenance (tool, pinned version, exact command,
UTC timestamp, target tree) is recorded in a way that keeps each artifact
machine-parseable (gitleaks: a sibling `.meta` line is forbidden, so the
provenance travels in the commit message + the t40 register row and the JSON
stays pure; the two `.txt` reports carry the tool's own header lines plus the
command line the tool itself prints). Findings are MEASURED, never hand-typed,
and the ACs gate report SHAPE, the gitleaks zero-leak invariant, and the
expected-finding classes of REQ-SEC-073 — with the register cross-check
phrased conditionally so it is green both before t40 (file absent) and after
(every parsed finding id has a row).
