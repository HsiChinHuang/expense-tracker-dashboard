## Goal

Land the persistence foundation for categories: the SQLAlchemy 2 `Category`
model on the merged `Base` (t6), Alembic revision `002` adding the `categories`
table with both CHECK constraints and the partial unique index (applies and
downgrades cleanly on SQLite, the merged dev/test engine), and an idempotent
seed routine that inserts exactly the ten Chapter 5 §5.9 system categories
(`is_system = TRUE`, `user_id = NULL`). After this issue the DB is ready for
the categories API (t11); no endpoint is built here.

## Acceptance criteria

- [ ] ac1 — `backend/app/models/category.py` defines `Category` on the shared `Base` matching REQ-DB-020 column-for-column (UUID PK generated in Python, nullable `user_id` FK to users, `name`/`color`/`icon`/`is_system`/`created_at`), and `__table_args__` carries both REQ-DB-021 CHECK constraints. A unit test instantiates a system row and a custom row and rejects (via constraint, on SQLite where CHECKs are enforced) an invalid HEX color and a system row with a user_id.
- [ ] ac2 — Alembic revision `002_*` (down_revision `001`) creates the `categories` table plus the REQ-DB-022 partial unique index; `alembic upgrade head` then `downgrade base` then `upgrade head` runs cleanly on a fresh SQLite file, and the existing revision-001/users behavior is untouched. A test asserts the two duplicate-custom-name inserts raise IntegrityError while two system-shaped rows (user_id NULL) are permitted by the partial index.
- [ ] ac3 — A seed routine (module under `backend/app/scripts/` or `backend/app/audit`-adjacent seed helper chosen at groom) inserts exactly the ten Chapter 5 §5.9 system categories with their pinned names and colors and is idempotent: invoking it twice leaves exactly ten system rows (REQ-DB-070/071). A test asserts count, names, `is_system`/`user_id` shape, and second-run no-op.
- [ ] ac4 — Seeding is wired per REQ-DB-072 on the merged startup/migration path without breaking the existing suite; `uv run pytest`, `ruff check .`, and strict `mypy .` all exit 0 with the new tests included and no regression to the merged backend suite count.
