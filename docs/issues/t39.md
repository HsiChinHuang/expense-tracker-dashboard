## Goal

Write the three operational documents that make Criterion 13 usable:
`ops/runbook.md` (quick-reference table of the seven symptoms and one section
per symptom carrying symptom / cause / diagnosis / action — cold start,
degraded health, 503 DATABASE_UNAVAILABLE, login failures, user data leak,
deployment failure, CI failure — plus the escalation path, monitoring and
alerting, backup/recovery with the `pg_dump` / `sqlite3 .dump` export and
restore commands, and the Render rollback procedure with its triggers and
limitations), `ops/health-check.md` (the `GET /api/v1/health` reference:
endpoint, no-auth, response schema, field meanings, state combinations, when
and how it is used by Render/UptimeRobot, and the explicit "what it does NOT
check" list), and `ops/logging.md` (the JSON structured log format with its
field reference, the five levels, the seventeen documented event names with
levels and fields, the never-logged list, destinations, viewing/filtering,
retention). Every documented value is derived from the merged code and the
Chapter 13 tables — the health response shape and the fallback log lines are
quoted from the shipped implementation and the already-green test assertions,
not invented — and every command the runbook tells an operator to run is a
real command that exists in this repo (Makefile targets, `docker compose`,
`curl /api/v1/health`, `pg_dump`, `sqlite3 .dump`).
