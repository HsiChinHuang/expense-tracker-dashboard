**Why the reference fill is honest, not fence-appeasement:**

- **Line ~105 (exporter sink write):** the exporter's contract is "export must never raise", but
  the only operations inside the try are `json.dumps(line)` and `self._sink.write(...)`. The line
  dict is all `str`/`int`/`None` (name, formatted ids, kind, status-code name) - `json.dumps`
  cannot fail on it. The sink is any file-like: a write failure is `OSError`, a closed file is
  `ValueError`. Catching exactly `(OSError, ValueError)` therefore keeps the never-raise contract
  for every failure the try can actually produce, while letting programming errors (`AttributeError`
  on a non-sink, etc.) surface instead of being silently swallowed - which is precisely why t8 bans
  the bare catch.
- **Line ~195 (ASGI span error marking):** the `use_span` context manager of
  `opentelemetry-sdk` (`use_span.__exit__`) already calls `span.record_exception(exc)`, sets
  `Status(StatusCode.ERROR)`, and re-raises for **every** `Exception` subclass - and deliberately
  does NOT intercept `BaseException`, so cancellation propagates untouched. The hand-written
  `except Exception as exc: record; set ERROR; raise` is byte-for-byte what the context manager
  already does; re-implementing the catch is exactly the class of silent-catch t8 forbids. Deleting
  the try/except (leaving `await self._app(scope, receive, send)` inside the `with`) preserves the
  recorded-exception + ERROR-status + re-raise behavior with one fewer swallow point. The
  `Status`/`StatusCode` imports (trace.py line 49) may become unused - the builder must let ruff
  (F401) decide and remove them only if ruff demands it.
