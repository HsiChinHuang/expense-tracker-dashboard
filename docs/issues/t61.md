# t61 - Move the sign-out control into the AppShell header so it works on every page, and remove the in-page control

**The defect.** The sign-out control hangs off the **dashboard page**, not off the shell. `frontend/src/pages/dashboard_page.tsx` renders the header row `<div data-testid="user-menu">` containing the signed-in username span and a `<button type="button" onClick={logout}>Log out</button>`, where `logout` is destructured from the merged `useAuth()` value. Meanwhile `frontend/src/components/layout/app_shell.tsx` — the component that actually wraps every authenticated page — renders a brand heading and four nav links and **no user affordance at all**.

That placement was correct when it was written: at t22 the dashboard was the only page inside the shell. t60 then re-nested `/expenses`, `/budgets` and `/categories` as children of the shell route so the header survives navigation to them. The consequence is that the sign-out control did not come along: on those three pages the shell header shows four nav links and no way to sign out, and the only way back to a signed-out state is to navigate to the dashboard first.

**The operator ruling this card implements (Q3a).** The control belongs in the **shell header**, and the in-page control is **removed**, not left behind. Two halves, both required: the button appears in `app_shell.tsx`, and the button disappears from `dashboard_page.tsx`. A card that adds the shell button and leaves the dashboard button is a duplicate, not a move.

**What the control must NOT become.** The merged `AuthContext.logout` action (t55-owned) is **not modified**, and this card does not reimplement any part of it. The button calls the context action; it does not clear storage itself. The redirect to `/login` after logout is likewise the **carried `ProtectedRoute` behaviour** — when the token becomes null the guard renders `<Navigate to="/login" replace>`. So no `useNavigate`, no `useLocation` and no local state appear in the shell; the only new hook use in that module is `useAuth()`, which the t60 card's "no auth state in the shell" note forbade **before** this ruling, and this card is the supersession record for that note.

**The router-less constraint that shapes the whole design.** The frozen `frontend/src/components/layout/app_shell.test.tsx` renders `<AppShell />` with **no Router and no AuthProvider**, and it is not edited by this card. Calling `useAuth()` in the shell body would throw there (`useAuth must be used within an AuthProvider`), so the control is placed in two module-local components: `LogoutSlot`, which reuses the **same** t18/t22/t60 `useInRouterContext()` fallback trick the module already uses for its nav links and renders `null` outside a Router, and `LogoutButton`, the leaf that reads the context and renders the button. The gate is a component rather than an early return around `useAuth()` so that no hook is ever called conditionally. The consequence, stated plainly: in the router-less frozen test the slot renders nothing and the three stored assertions never move; inside the app, where a provider always exists, the button renders.
