## Goal

Deliver the frontend auth vertical on the merged t2 skeleton: the centralized
axios client with auth/error interceptors and error normalization, a typed
`api/auth.ts` module, AuthContext owning user/token state (token validated on
mount via /auth/me), ProtectedRoute/PublicOnlyRoute guards wired into a nested
route table, and the LoginPage/RegisterPage forms (React Hook Form + Zod). All
behavior is proven with Vitest + RTL + MSW — no live backend needed — so a
reviewer sees register → auto-login → protected content → logout → redirect
guarded, entirely in jsdom.

## Acceptance criteria

- [ ] ac1 — `frontend/src/api/client.ts` exports a single axios instance configured with `import.meta.env.VITE_API_BASE_URL` and a 10_000 ms timeout; a request interceptor attaches `Authorization: Bearer <localStorage token>` when a token exists; a response interceptor on 401 removes the `token` key from localStorage and redirects to `/login` (via an injected callback or `window.location` — testable). `frontend/src/api/auth.ts` exports typed `register`, `login`, `getMe` functions mapping 1:1 to the Chapter 7 §7.3 endpoints. Errors are normalized to `{status, code, message, field?}` with a distinct code for network errors (REQ-FE-040/041). Unit tests (MSW) prove: header attached when token present; 401 clears the key and triggers the redirect hook; a 409 `{detail, code, field}` body normalizes with the backend code preserved. (REQ-TECH-007, REQ-ARCH-070.)
- [ ] ac2 — `frontend/src/context/auth_context.tsx` exports `AuthProvider` and `useAuth()` returning `{ user, token, isLoading, login, register, logout }` (REQ-FE-031). On mount, if a token exists in localStorage under key `token`, it calls `/auth/me` to validate; a 401 response clears the token and leaves state logged-out (REQ-ARCH-042). `login`/`register` store the returned token and user; `logout` clears both. `main.tsx` nests providers QueryClientProvider → BrowserRouter → AuthProvider → App (MonthProvider/ToastProvider are later milestones — do not stub them here). RTL+MSW tests cover: valid stored token → user populated; invalid stored token → token removed, user null; login flow stores token+user; logout clears both.
- [ ] ac3 — `ProtectedRoute` renders a spinner while `isLoading`, redirects to `/login` with the attempted location in router state when unauthenticated, and renders children when authenticated (REQ-FE-012). `PublicOnlyRoute` redirects logged-in users from `/login`/`/register` to `/` (REQ-FE-014). `App.tsx` (or router module) wires the nested route table: `/login`, `/register` public; `/` protected (REQ-FE-010/011). RTL tests prove: unauthenticated visit to a protected route lands on /login; authenticated visit renders content; authenticated visit to /login redirects to /; the saved `from` location is available in location state.
- [ ] ac4 — `LoginPage` (email + password via React Hook Form + Zod schema mirroring the backend rules) submits through `useAuth().login`, shows the normalized error inline on 401, and on success navigates to the `from` location or `/` (REQ-FE-013/REQ-FE-060). `RegisterPage` (email, username, password, confirm password; Zod validation on blur including min-8 password and 3–50 no-space username rules) submits through `useAuth().register`, auto-logs-in on success, and renders field-level errors from the backend 409/422 `{code, field}` payload (REQ-FE-061). RTL+MSW tests: successful login navigates and content renders; failed login shows the error message; register validation blocks client-side before submit (no network call asserted via MSW handler non-invocation); backend 409 on register surfaces on the email field.
- [ ] ac5 — MSW handlers for `/auth/login`, `/auth/me`, `/auth/register` live in `frontend/src/test/` (REQ-FE-133 subset; categories/expenses/dashboard handlers arrive with their milestones). No component performs raw `fetch`/`axios` outside `src/api/` (REQ-ARCH-044 — lint-enforceable grep). `react-hook-form` and `zod` are added as pinned dependencies in `package.json` + `package-lock.json` (REQ-TECH-006; the t2 ac6 ban is lifted for phase_2 — the check is that versions are exact pins, no ranges).
- [ ] ac6 — Quality gates on the Windows-toolchain pattern from t2/t4: `npm install` succeeds, `npm test -- --run` exits 0 with the t2 app-shell tests still passing plus at least 8 new auth-related test cases, `npx tsc --noEmit` exits 0, `npm run lint` exits 0. No `any` in new code (coding_standards.md).
