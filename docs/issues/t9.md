## Context

t9 delivers the frontend auth vertical on the merged t2 skeleton and t4 layout
shell. The backend contract is merged (t8 @ main): `POST /api/v1/auth/register`
→ 201, `POST /api/v1/auth/login` → 200 `{access_token, token_type, user}`,
`GET /api/v1/auth/me` with `Authorization: Bearer`; 401 codes
`UNAUTHORIZED` / `TOKEN_INVALID` / `TOKEN_EXPIRED` / `USER_INACTIVE`; 409
`DUPLICATE_EMAIL` / `DUPLICATE_USERNAME`; 422 `VALIDATION_ERROR` per field; the
error body is `{detail, code, field}`.

Groom-time facts established by probing the merged tree (Builder may rely on
these; do not re-derive):

- **Component dir**: the merged skeleton ships `frontend/src/components/common/`
  (t0). Guards therefore live at
  `frontend/src/components/common/protected_route.tsx` and
  `.../public_only_route.tsx`. The survey draft's `src/components/auth/` is
  superseded — that directory does not exist on main.
- **Router module**: main ships `frontend/src/app.tsx` + `frontend/src/main.tsx`
  (snake_case per coding_standards.md). `App.tsx` in the survey draft means
  `frontend/src/app.tsx`.
- **No resolver package**: `@hookform/resolvers` is NOT in the lockfile and t9
  adds no dependencies beyond react-hook-form + zod. The zod→RHF bridge is a
  ~20-line hand-rolled resolver in `frontend/src/utils/validation.ts`
  (`zodResolver(schema)` returning RHF's `Resolver` shape, plus
  `applyApiErrors(errors, setError)` mapping `{field, message}` onto field
  errors). Proven to work with react-hook-form 7.53.2 + zod 3.23.8.
- **Test runner interface**: vitest's `-t` name filter is mangled by the cmd.exe
  shim on this host and silently matches nothing (exit 0 — a vacuous-pass trap).
  The pinned commands therefore use `--reporter=json` and assert on the JSON
  payload (`numFailedTests` + exact `"status":"passed","title":"..."` greps).
  Test titles are frozen by the ACs below and contain no apostrophes for this
  reason.
- **MSW**: msw 2.3.5 with axios (XHR adapter) under jsdom intercepts correctly;
  `server.use(...)` overrides work; a handler that throws simulates a network
  error. `setupServer` must be configured `onUnhandledRequest: 'error'`.
- **No live backend**: no test may touch `localhost:8000`. All auth tests run on
  MSW fixtures mirroring the t8 contract.
- **Token key / redirect**: localStorage key is exactly `token`; the 401
  interceptor removes it and sets `window.location.href = '/login'` (tests stub
  `window.location` via `Object.defineProperty`).
- **AppShell**: t4's layout shell is NOT rewritten here — route-outlet
  integration only, minimal diff.
- **Provider nesting** (`main.tsx`): QueryClientProvider → BrowserRouter →
  AuthProvider → App. MonthProvider/ToastProvider are phase_3/phase_4 — do not
  stub them.
- Baseline on main: 3 auth-adjacent tests exist (t2/t4 app-shell tests); the
  merged suite is 3 nodes. The reference implementation for these ACs was
  built and run in a scratch tree during groom (6 files / 26 nodes green, plus
  tsc / lint / build rc=0); the scratch tree is deleted — the Builder still
  implements for real on main.

## Goal

Deliver the frontend auth vertical on the merged t2 skeleton: the centralized
axios client with auth/error interceptors and error normalization, a typed
`api/auth.ts` module, AuthContext owning user/token state (token validated on
mount via /auth/me), ProtectedRoute/PublicOnlyRoute guards wired into a nested
route table, and the LoginPage/RegisterPage forms (React Hook Form + Zod). All
behavior is proven with Vitest + RTL + MSW — no live backend needed — so a
reviewer sees register → auto-login → protected content → logout → redirect
guarded, entirely in jsdom.
