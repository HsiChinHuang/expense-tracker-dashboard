## Goal

`README.md:56-57` tells the reader that the seeded demo account "is never available on the
hosted app". After the operator's decision that sentence is false, and a README that states a
false thing about the deployed app is worse than a README that says nothing. Delete the clause,
keep every other word of the paragraph, keep the file at 421 lines, and do not replace the
denial with an advertisement.

## Context

**The operator decision (locked; not re-litigated in this card).** The operator will provision
`demo@example.com` / `demo-password-123` on the hosted Render app by running the EXISTING seed
script against the hosted database. Zero product-code change: `npm run seed:demo` already
resolves the app settings and `backend/app/scripts/seed_demo.py` already exists, so provisioning
is an ops action, not a feature. Consequence: the README sentence
`it is never available on the hosted app` is a statement about production that is no longer
true, and it must go.

**The second half of the decision, which is the part that constrains the fix.** The README must
NOT advertise a hosted demo login either. The operator's words: the account exists but is not
announced. The reasoning is measured, not aesthetic -

- a careful reader learns nothing new: the credentials are already printed two sentences
  earlier in the same paragraph,
- a careless reader who reads "the demo account works online" and signs in at the hosted URL
  with the shared credentials lands in a database that holds the NEXT person's expenses, not an
  empty sandbox.

So the fix is a DELETION, not a rewrite. The paragraph keeps saying what the seed does locally
and stays silent about what the hosted app holds. Silence is the correct outcome; both "never
available" and "works online" are wrong.
