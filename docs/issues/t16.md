## Goal

Build the frontend data layer for the three new resources on the merged t9
client: typed `api/categories.ts`, `api/expenses.ts`, `api/budgets.ts` mapping
1:1 to the merged Chapter 7 endpoints (money typed as strings, dates as
`YYYY-MM-DD` strings); a `queryKeys` factory; TanStack Query hooks
(`use_categories`, `use_expenses` with filter params, `use_expense_mutations`,
`use_budget`, `use_budget_mutations`, `use_create_category`,
`use_delete_category`) implementing the REQ-FE-051 invalidation matrix; and
MSW handlers for every phase_3 endpoint so t17/t18 and this issue's own tests
run fully in jsdom. No page or form UI here.

## Notes (survey rulings)

- BOUNDARY: no frontend UI in t16 — no pages, no route changes, no form components.
  Test files may mount inline harness components (QueryClientProvider + observer) inside
  the test files only; that is test scaffolding, not UI. t17/t18 own all user-facing screens.
- Invalidation proof mechanism (ac3, non-weasellable): each mutation test mounts a live
  QueryClientProvider with (a) the real resource observer query and (b) a dummy observer
  keyed exactly `["dashboard","probe"]` whose queryFn calls a counted MSW handler. The
  assertions are handler call counts observed before/after the mutation (refetch = count
  increment), plus negative controls (unrelated resources' handlers NOT called). Category
  mutations must NOT refetch the dashboard observer (REQ-FE-051: categories invalidate
  ["categories"] only). Reading the invalidation code instead of observing refetch traffic
  does not satisfy ac3.
- Contract pins (mirrored from merged routers/schemas, main @ 5c03bb0): categories
  GET+POST on `/api/v1/categories` (list body is the OBJECT WRAPPER `{"categories":[...]}`)
  and DELETE `/api/v1/categories/{id}` -> 204; expenses GET (envelope `{items,total,page,page_size}`,
  filters year_month/category_id/page/page_size) + POST on `/api/v1/expenses`, GET/PUT/DELETE on
  `/api/v1/expenses/{id}` (DELETE -> 204); budgets GET/PUT/DELETE on `/api/v1/budgets/{year_month}`
  (absent-month GET -> 200 `{"year_month":"YYYY-MM","amount":"0.00"}`; DELETE -> 204). Money is a
  2-decimal STRING in every type; dates `YYYY-MM-DD` strings; timestamps ISO strings. Handlers.ts
  uses literal `/api/v1/...` paths like the t9 auth handlers.
- Duplication check: merge_test_index.json has 82 entries (t0-t15), zero t16 entries; merged
  frontend test files are the t9 six (26 nodes, all stay untouched); no existing test touches
  categories/expenses/budgets api, query_keys, hooks, or phase_3 handlers. All 24 new nodes are
  new files/titles. ac5 is the composite gate and is EXCLUDED from merge_test_index.json per the
  t10-t15 precedent (the 24 node IDs are what gets appended at close).
- Environment note for the Builder: the worktree has NO node_modules (neither root nor
  frontend/); `npm ci` in `frontend/` (or the cmd.exe toolchain equivalent) is required before
  the vitest commands can pass. Fail-before rc=1 for every AC is attributable solely to the
  missing files (each command's first leg is `test -f <new file>`).
