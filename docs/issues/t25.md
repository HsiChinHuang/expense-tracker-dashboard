## Goal

Replace the phase-1 placeholder database behavior with the real FR-DB-1
machine, and make health honest:

1. `create_db_engine(url)` — SQLite URLs build directly (merged PRAGMA
   wiring untouched); any non-SQLite URL attempts PostgreSQL with a
   5-second connect timeout and, on failure, logs a WARNING and returns a
   SQLite engine on `sqlite:///./fallback.db` with the same PRAGMA wiring,
   exposing whether fallback is active (REQ-BE-130/133).
2. Startup initialization — when fallback is active the app creates tables
   via `create_all()` (never Alembic, REQ-DB-083) and runs the merged
   system-category seed routine so REQ-PROD-013 "system categories always
   available" holds in fallback (REQ-BE-131, REQ-DB-072); the primary path
   logs primary initialization and stays Alembic-owned.
3. Health — `/api/v1/health` reports the LIVE state: `database` derived from
   the engine dialect, `fallback_active` from the fallback flag, `status`
   "ok"/"degraded" accordingly, `version` unchanged (REQ-BE-132).

Contract safety (survey ruling 2): the four-field schema
(`DatabaseBackend = Literal["postgresql","sqlite"]`,
`HealthStatus = Literal["ok","degraded"]`) already admits the live values, so
the merged `tests/integration/test_health_api.py` titles and assertions stay
BYTE-IDENTICAL and green — its assertions are set/domain checks plus
`(status == "ok") is (fallback_active is False)`, never a literal
"postgresql". The phase-1 constant `DATABASE_BACKEND: Final[DatabaseBackend] =
"postgresql"` in `app/routers/health.py` is DELETED by this card and is the
card's fail-before anchor.
