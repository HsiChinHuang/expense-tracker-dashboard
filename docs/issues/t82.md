## Goal

Make the autonomy boundary a machine-readable artifact instead of a paragraph,
and give the response loop its two executable steps: how to roll back, and how
to PROVE recovery. The policy is the card that says what an AI responder may
never do; `verify-recovery.sh` is the card that makes "it recovered" a measured
claim.

## Measured base state (measured at survey on 245cd49, re-measure at groom)

  the `runbooks/` directory inside it.
- The recovery condition is a merged contract, not an invention:
  `backend/app/routers/health.py` lines 7-8 - `status` is `"ok"` exactly when
  `fallback_active` is False. So `verify-recovery.sh` asserts two fields of one

## AC draft (groom will fence these - target 5 fenced ACs, inside max_acs=6)

- **ac1 - the policy exists, parses, and denies the three forbidden actions.**
  `autonomy-policy.yaml` parses under the pinned self-contained validator and
  contains an explicit deny list covering restart-of-production, database
  mutation and merge. The fence asserts each of the three denies by name.
- **ac2 - the policy allows the two permitted action classes.** An explicit
  allow list covering read-only log and metric reads and report writing, each
  with its scope stated (which paths may be written, which endpoints may be
  read). The fence asserts both allows and the scope sentence for each.
- **ac3 - the two runbooks exist, are bash-clean and side-effect-scoped.**
  `bash -n` passes on both; `rollback.sh` names what it rolls back and refuses
  to act without an explicit target argument; neither script contains a merge
  command, a DB write statement, or a non-loopback host (grep-enforced), which
  is the policy's deny list expressed as a test.
- **ac4 - verify-recovery.sh asserts the real recovery condition and fails
  otherwise.** The script asserts health `status` == `ok` AND
  `fallback_active` == `false`, exits 0 only when both hold, and exits non-zero
  with a readable reason otherwise. The fence proves the assertion strings and
  the non-zero path (a stub/unreachable endpoint must produce non-zero, not a
  silent pass).
- **ac5 - delta purity.** Only the three allow-listed files are added;
  `ops/runbook.md`, `ops/diagnosis.md`, `incident-response/collect-evidence.sh`
  and `README.md` (t80's), `observability/`, `backend/`, `security/`,
  `openapi.yaml` and every `docs/` file are byte-clean against the named
  immutable ref.

## Constraints (hard)

- Exactly 3 files: `incident-response/autonomy-policy.yaml`,
  `incident-response/runbooks/rollback.sh`,
  `incident-response/runbooks/verify-recovery.sh`.
- This card is the AUTONOMY AUTHORITY. t81's schema enum and t84's recorded
  actions must be subsets of its allow list; nothing here restates t81's schema
  as a competing definition.
- The denied set is non-negotiable and must be explicit, not implied: restart
  of production, database mutation of any kind, and merge. A policy that only
  lists allows (and thereby implies denies) FAILS ac1.
- `rollback.sh` must be SAFE BY CONSTRUCTION for this repo: it is a documented,
  argument-gated procedure that refuses to run without an explicit target, and
  it never runs against production or against the compose stack. If the honest
  content of a rollback here is "redeploy the previous image, per the deployment
  record", the script says that and requires a human target argument - it does
  not fake an automated rollback it cannot perform locally.
- No script in this card may start a server, bind a port, touch Docker, or
  contact a non-loopback address. Read-only HTTP GET against the local health
  endpoint is the only network shape permitted, and the card says so.
- No product-code change, no `openapi.yaml` change, no new dependency, no edit
  to `ops/` (t85 owns those two files).
- Bash style: `set -u`, explicit exit codes, no `/dev/null` through cmd.exe
  chains, git calls via `cmd.exe /d /c "..."` where git is needed.
