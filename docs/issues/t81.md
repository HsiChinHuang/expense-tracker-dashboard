## Goal

Define WHAT an AI responder is asked to do and WHAT it must answer with, in a
form a machine can reject: a task prompt that states the read-only scope and
the evidence it may read, and a JSON Schema that its answer must validate
against. Without the schema, "the AI analysed the incident" is an uncheckable
claim; with it, t84's `response.json` is a gate input.

## Measured base state (measured at survey on 245cd49, not assumed)

- There is no `incident-response/` directory at base; t80 creates it, so this
  card branches after t80 merges and adds exactly its own two files plus one
  validator.
- A validator is available on this machine WITHOUT a new dependency, and the
  card pins which one it uses:
  `node -e "require('./node_modules/ajv/package.json').version"` -> ajv 8.20.0
  in the ROOT `node_modules` (already a project dependency), and
  `python3 -c "import jsonschema"` -> jsonschema 4.10.3 under WSL. The pinned
  command uses the ROOT ajv via `node` (no network, no install, no pip), and
  the card records the measured version string so a reviewer can reproduce it.
- The evidence bundle shape the responder reads is t80's manifest (incident id,
  collected-at, endpoint, four leg statuses, tree hash). The schema's input
  assumptions must match that file, which is why t81 depends on t80.

## AC draft (groom will fence these - target 4 fenced ACs, inside max_acs=6)

- **ac1 - the schema exists, is valid JSON, and is a valid JSON Schema.** The
  pinned command parses `response.schema.json` and compiles it under ajv 8
  (draft 2020-12 or draft-07, stated explicitly in the file via `$schema`).
  RED at base because the file does not exist.
- **ac2 - the schema demands the fields an incident answer must carry.**
  Required: a summary, a classification/severity, a root-cause hypothesis, an
  evidence reference list (paths under the incident directory), the actions
  taken with each action constrained to the ALLOWED set (an enum, so an
  out-of-policy answer is rejected by the schema and not only by prose), and a
  confidence. A fixture answer missing any required field must fail
  validation - the negative control is part of this AC.
- **ac3 - the validator command is pinned, self-contained and reproducible.**
  The fence runs the validator against a committed minimal fixture answer and
  asserts exit 0, then against a deliberately broken fixture and asserts
  non-zero, both without network and without an install step. The command is a
  single self-contained `bash -c` one-liner (the t72/t73/t74 appendability
  rule).
- **ac4 - the prompt states the boundary and does not overstate it.**
  `responder-task.md` names the evidence files it may read, states that the
  responder is READ-ONLY (no restart, no DB mutation, no merge) and points at
  `incident-response/autonomy-policy.yaml` as the authority rather than
  restating a competing rule set, and states what the responder must NOT claim
  (it must not assert recovery without the verification output). Delta purity:
  only the three allow-listed files are added.

## Constraints (hard)

- Exactly 3 files: `incident-response/responder-task.md`,
  `incident-response/response.schema.json`,
  `incident-response/validate_response.mjs` (the pinned validator; a `.mjs`
  under `incident-response/` keeps the root clean and is not a build input).
  If the groom prefers a Python validator, it must be named in the card before
  the fence is written - the fence and the file must agree.
- No new dependency, in any language. ajv is already in the root
  `node_modules`; `jsonschema` under WSL is the fallback and the card states
  which is pinned.
- The schema is a CONTRACT, not documentation: it must reject the wrong shape,
  and the card must show the rejection measured. A schema that accepts
  everything is a FAIL even if every other leg is green.
- The allowed-action enum in the schema must be a SUBSET of what t82's policy
  allows; the card states that relationship in one sentence, and t82 remains
  the authority.
- No product-code change, no backend change, no `openapi.yaml` change, no
  Docker, no network call in any fence.
- The prompt must not instruct the responder to read `.env`, `~/.ssh`, tokens
  or any secret (the coding-standards forbidden-actions table), and must say so.
