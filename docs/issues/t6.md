## Metadata

- Milestone: phase_2_auth
- Requirements: REQ-DB-010 (users table: id UUID PK, email VARCHAR(255) UNIQUE NOT NULL indexed, username VARCHAR(50) UNIQUE NOT NULL, hashed_password VARCHAR(255) NOT NULL, is_active BOOLEAN NOT NULL default true, created_at/updated_at timestamps), REQ-DB-011 (email unique + case-insensitive, username unique + case-sensitive, password never plaintext, is_active=false blocks login but preserves data), REQ-SEC-020 (hashed_password column stores bcrypt hashes; no plaintext), REQ-SEC-052 (UNIQUE on email, username), REQ-TECH-032 (UUIDs generated in Python for SQLite portability), REQ-TECH-031 (SQLAlchemy only), REQ-PLAN-020 (phase 2 task 2.1: user model + migration)
- Source: requirements/Chapter5_DatabaseDesign.md §5.3.1, §5.3.4; requirements/Chapter12_SecurityandAudit.md §12.3.1

## Goal

Define the SQLAlchemy 2.0 `User` model and the first Alembic revision so the
`users` table exists with the Chapter 5 §5.3.1 shape on both SQLite (dev) and
PostgreSQL (later), with the migration chain started at a single named
revision. Passwords are representable only as hashes (`hashed_password`);
hashing itself is t7's job — this issue only makes the table and model correct.

## Acceptance criteria

- [ ] ac1 — `backend/app/models/user.py` defines a SQLAlchemy 2.0 declarative `User` (PascalCase per coding_standards.md) mapped to table `users`, with exactly the REQ-DB-010 columns and types: `id` PK of generic `sa.Uuid` whose value is produced by a **Python-side** `default=uuid.uuid4` (no `gen_random_uuid()`/`server_default` on the id — REQ-TECH-032), `email` `String(255)` unique + not null + indexed, `username` `String(50)` unique + not null, `hashed_password` `String(255)` not null, `is_active` `Boolean` not null defaulting to true, `created_at`/`updated_at` `DateTime` not null with `server_default=func.now()` (`updated_at` additionally `onupdate=func.now()`). No plaintext-password column exists and **no table other than `users` is registered on the declarative `Base.metadata`** (categories/expenses/budgets/audit_logs are phase_3 scope). A unit test asserts the mapped column set/uniqueness/lengths, that `Base.metadata.tables == {"users"}`, and that a session insert yields a `uuid.UUID` `id` with non-null timestamps — so a DB-generated id or a missing timestamp default fails, not just a typo'd name. (REQ-DB-010.)
- [ ] ac2 — Alembic revision `001` exists as exactly one file `backend/alembic/versions/001_*.py` declaring `revision = "001"` and `down_revision = None` (single head, chain root), and the migration is hand-written (explicit `op.create_table`/`op.drop_*`), not an autogenerate dump. Against a tmp SQLite file via `DATABASE_URL`, from `backend/`: `uv run alembic upgrade head` creates **only** `users` + `alembic_version` with the seven ac1 columns and leaves one `alembic_version` row; a raw (ORM-free) `INSERT` that supplies only `id`/`email`/`username`/`hashed_password` proves the **DB-level** defaults (`is_active` truthy, `created_at`/`updated_at` non-null) — so a model-only default does not pass; `uv run alembic downgrade base` then **removes the `users` table**; a second `upgrade head` recreates it (reversibility, run in that order inside one command). (REQ-DB-010, REQ-SEC-052.)
- [ ] ac3 — Uniqueness is proven by a real `IntegrityError` round-trip at the DB layer (no docstring-dependent AC): two unit tests each insert a first user, commit, then insert a second user in a new session and assert `pytest.raises(IntegrityError)` on commit — one with a **duplicate email** (same case, different username) and one with a **duplicate username** (case-sensitive: the second row uses a different-case username and MUST still be rejected, proving case sensitivity). REQ-DB-011's *case-insensitive* email half is explicitly NOT claimed here: normalization to lowercase is the service layer's job (t8, REQ-BE-050) and the model/migration docstrings MUST state that the DB enforces uniqueness on the stored (already-normalized) value — that statement is a Definition-of-Done item, not a verification command. (REQ-DB-011, REQ-SEC-052.)
- [ ] ac4 — Timestamp/default behavior is proven by two unit tests on a real SQLite round-trip: (a) create a user, commit, sleep > 1 s, update `username`, commit, `session.refresh(...)`, then assert `updated_at > <pre-update value>` **and** `updated_at >= created_at` (the strict inequality is what proves an `onupdate` mechanism exists — a plain `server_default`-only column leaves `updated_at` equal and fails); (b) insert a user **without** passing `is_active` and assert the reloaded row's `is_active is True`. (REQ-DB-010, REQ-DB-011.)
- [ ] ac5 — No regression and quality gates: from `backend/`, `uv run pytest` exits 0 (t1 smoke + t3 health + t5 config/database tests plus the new `tests/unit/test_user_model.py` all green — importing the model must not break `create_app()`/health), `uv run ruff check .` exits 0, `uv run mypy .` (strict) exits 0. No `except Exception`; complete annotations; Google docstrings (coding_standards.md).

Notes for Builder and Verifier (all shapes probed on current main during this
groom, and positively proven against a reference implementation):

- **Required test node IDs (part of the contract).** New module
  `backend/tests/unit/test_user_model.py`, class `TestUserModel`, functions:
  `test_creates_user_with_python_uuid_default_and_typed_columns` (ac1),
  `test_duplicate_email_raises_integrity_error` +
  `test_duplicate_username_raises_integrity_error` (ac3),
  `test_updated_at_refreshes_on_update` + `test_is_active_defaults_true_on_insert`
  (ac4). coding_standards.md naming is satisfied; a missing module/node makes
  pytest exit 4 (usage error), which is a fail, not a skip.
- **Test isolation (t5 precedent).** ac1/ac3/ac4 pin
  `DATABASE_URL=sqlite:////tmp/t6_ac1.db|t6_ac3.db|t6_ac4.db` and `rm -f` their
  own file; ac2 pins `/tmp/t6_ac2.db`. The absolute 4-slash form is deliberate
  (a relative `sqlite:///./t.db` would land in `backend/`). Tests must fall
  back to a per-test `tmp_path` SQLite file when `DATABASE_URL` is unset so the
  ac5 full-suite run never touches `backend/dev.db` either.
- **ac2 is the migration contract and it is order-sensitive.** It deliberately
  runs `upgrade → raw-insert check → downgrade → absence check → upgrade`,
  which is stronger than "exit codes for three CLI calls": the raw `sqlite3`
  insert proves `is_active`/`created_at`/`updated_at` **server-side** defaults
  exist in revision 001 (a model-only `default=` fails with
  `NOT NULL constraint failed: users.is_active` — reproduced during groom),
  and the post-`downgrade base` check proves `downgrade()` really drops the
  table. `tables == {"users", "alembic_version"}` rejects creating any extra
  phase_3 table in this revision. The `revision`/`down_revision` greps plus
  `alembic heads` line count pin the chain root and reject a second head.
- **ac2 avoids git on purpose** (WSL cannot resolve worktree gitdir pointers);
  "revision file is tracked" is a Definition-of-Done item instead (t5 precedent).
- **ac3 is now a real IntegrityError round-trip, not a docstring check**
  (review_plan mandate). The username test MUST use a different-case second
  value (e.g. `same` then `SAME`) so SQLite's BINARY collation is exercised and
  case-sensitive username uniqueness is actually demonstrated; SQLite compares
  `'A' <> 'a'`, so a wrongly-collated implementation fails. Email uniqueness is
  asserted on the exact stored value only — case-insensitivity is t8's
  normalization layer (see Out of scope).
- **ac4's strict inequality is the discriminator.** `updated_at >= created_at`
  alone passes with `server_default` only and no `onupdate`; the reference
  implementation proves `updated_at > original` after a > 1 s sleep (SQLite
  `CURRENT_TIMESTAMP` has 1 s resolution, hence the sleep). Keep the sleep ≥ 1 s.
- **mypy-strict / ruff traps found while building the reference implementation**
  (all reproduced and resolved; `ruff check .` and `mypy .` both exit 0 there):
  (1) `User.__table__` is typed as `FromClause`, so `table.name` /
  `table.columns[...].type.length` fail mypy strict — annotate as
  `table = cast(Table, User.__table__)` and `cast(String, table.columns["email"].type).length`;
  (2) `alembic/env.py` gains `from app.models.user import Base` — it must go in
  the **top** import block (ruff `E402` rejects an import after

  (3) in `001_*.py`, `import sqlalchemy as sa` and `from alembic import op`
  need a blank line between the first- and third-party blocks (ruff `I001`).
- **ac5 is a pure non-regression gate** and therefore exits 0 on current main
  (verified rc=0). Stated per the t3/t5 precedent: t6's new tests raise the
  collected count; the AC requires the pre-existing t1/t3/t5 tests to stay
  green and the gates to stay clean, which is why it is the one AC that passes
  pre-implementation.
- `export PATH="$HOME/.local/bin:$PATH"` makes the Linux `uv` binary resolvable
  (t1..t5 precedent); `command -v uv >/dev/null || exit 1` turns a missing
  toolchain into a clear fail instead of a 127. t6 is backend-only: no

- Verifier: run `uv sync` in `backend/` first if the worktree venv is cold. t6

**Storage simplification to document, not to fight:** REQ-DB-010 asks for
TIMESTAMPTZ, but the dev/test engine is SQLite, where `sa.DateTime` stores a
naive string and timezone fidelity is lost. Use `DateTime` +
`server_default=func.now()` (+ `onupdate=func.now()` on `updated_at`) so the
same DDL works on PostgreSQL later; state the simplification in a docstring.
SQLite's `CURRENT_TIMESTAMP` has **1 s resolution** — that is why ac4 sleeps > 1 s.

## Out of scope

- Password hashing (bcrypt/passlib `hash_password`/`verify_password`) and JWT: **t7**. t6 only stores an opaque `hashed_password` string.
- Register/login/me endpoints, the auth service that normalizes email to lowercase (REQ-BE-050), `get_current_user`, and the 409 `DUPLICATE_EMAIL`/`DUPLICATE_USERNAME` mapping of this issue's `IntegrityError`: **t8**.
- Case-insensitive email lookup via `func.lower()` queries or a `COLLATE NOCASE`/`citext` column: **t8** (service-layer normalization is the accepted mechanism per REQ-BE-050; the DB keeps a plain UNIQUE on the stored value).
- `is_active = false` login blocking (REQ-DB-011 second half) — the column and its default are in scope; the enforcement lives in t8's `get_current_user`/`login_user`.
- `categories`, `expenses`, `budgets`, `audit_logs` tables and their FK/cascade rules (REQ-DB-020 … 040): **phase_3_crud**. ac2's exact-table-set assertion enforces this.

- `Base.metadata.create_all()` as a substitute for migrations in app startup, seed scripts, and `make seed`: later phases (`backend/app/scripts/` stays empty).

## Constraints

- SQLAlchemy 2.0 style only (`Mapped` / `mapped_column`, `DeclarativeBase`); no legacy 1.x `column()`/`declarative_base()` patterns (REQ-TECH-021).
- UUID generated in Python, not by DB-specific functions (`gen_random_uuid()` is PostgreSQL-only and forbidden — REQ-TECH-032). Use `sa.Uuid` with `default=uuid.uuid4`; do not use `postgresql.UUID` directly and do not put a `server_default` on `id`.
- Timestamps must work on SQLite: `DateTime` with `server_default=func.now()` (+ `onupdate=func.now()` for `updated_at`); document the SQLite timestamp simplification rather than inventing SQLite-only hacks.
- `is_active` needs BOTH a Python-side `default=True` (ORM inserts) and a `server_default` in revision 001 (ac2's raw-insert check proves the server side).
- Only the `users` table in this issue; the 001 revision is scoped so later revisions chain cleanly (`down_revision = None`, single head).
- No bcrypt/passlib usage, no auth endpoints, no Pydantic schemas, no `app/services/` code — t7/t8 own those.
- Files touched: `backend/app/models/user.py`, `backend/app/models/__init__.py` (re-export), `backend/alembic/versions/001_initial_schema.py`, `backend/alembic/env.py` (replace `target_metadata = None` with the model metadata; import at the top of the file for ruff `E402`), and `backend/tests/unit/test_user_model.py`. Nothing else — `main.py`, health contract, `config.py`, `database.py`, `pyproject.toml`, `uv.lock`, `Makefile`, `.env.example` stay untouched.
- Python style per coding_standards.md: 4-space indent, snake_case modules, PascalCase classes, Google docstrings, complete annotations (mypy strict), specific exceptions only (no `except Exception` — catch `IntegrityError` in tests).
- Test naming per coding_standards.md: `test_<module>.py`, `class Test<Module>`, `test_<action>_<expected>`; the five node IDs pinned above are contractual.
- 5 AC / 4 production+test files / expected diff well under `max_diff_lines=300` (`limits.issue_granularity.*`, warn_only).
