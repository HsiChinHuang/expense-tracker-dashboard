## Context

**What this card is.** The operator-reported defect: the expense form asks for a
36-character category UUID that the UI never shows anywhere, so a real user
cannot create an expense without devtools. The fix is a `<select>` populated from
the EXISTING merged `use_categories` hook, showing category NAMES (system rows
plus the caller's own custom rows), submitting a valid `category_id`, prefilling
correctly on edit, and hinting at the Categories page when no suitable category
exists. Operator-approved scope, re-confirmed at review_plan.

**Measured base state (re-measured at groom on 9ae21b2, not assumed).**
`frontend/src/components/forms/expense_form.tsx` (cr-sha256
f7e9befd9288522cdf38d3ea0d328d701ff9f34045523b5a48352194129c14ea) renders a
label whose text is `Category id` over a bare `<input>` bound to `category_id`;
the zod leg `expenseFormSchema.category_id` in `frontend/src/utils/validation.ts`
is `z.string().min(1, 'Category is required')` - it never validates the shape, so
any non-empty string passes the client. `frontend/src/hooks/use_categories.ts`
exists, is tested, and is already consumed by `expenses_page.tsx` (the Category
filter select is the precedent markup: `<option>` per `category.name`, value =
`category.id`). The MSW fixture `frontend/src/test/handlers.ts` serves exactly
ONE category (`demoCategory`, name "Food") from `GET /api/v1/categories`, so a
two-category test must add its second option through a per-test `server.use`
override - the shared fixture is FROZEN for this card. `e2e/fixtures/helpers.ts`
