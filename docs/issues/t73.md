## Goal

A user adding or editing an expense must be able to choose a category by NAME.
Today they cannot: the form asks for a 36-character UUID and the UI never shows
one anywhere.

## Measured base state (re-measured at survey, not assumed)

- `frontend/src/components/forms/expense_form.tsx` lines 112-124: a label whose
  text is `Category id` and a bare `<input>` bound to `category_id`. The zod leg
  is `frontend/src/utils/validation.ts:89` `category_id: z.string().min(1, 'Category is required')`
  - it never validates the UUID shape, so any non-empty string passes the client
  and the backend rejects it later.
- `frontend/src/hooks/use_categories.ts` already exists and is tested
  (`frontend/src/hooks/use_categories.test.tsx`); it is the merged
  TanStack Query hook over `GET /api/v1/categories` (object wrapper
  `{categories: [...]}`, system rows first).
- The Categories page never prints ids: `grep -n "\.id" frontend/src/pages/categories_page.tsx`
  shows `category.id` used only as a React `key` and for the delete mutation. So
  a valid id is unobtainable without devtools.
- Pins that own the bare-input behaviour and MUST be dispositioned explicitly:
  - `frontend/src/components/forms/expense_form.test.tsx:40` -
    `fillForm` does `fireEvent.change(screen.getByLabelText('Category id'), ...)`.

  - `frontend/src/pages/expenses_page.test.tsx` - greps found NO category-id

## AC draft (groom will fence these)

- **ac1 - the control is a select of names.** The category field renders a
  `<select>` whose options come from the merged `use_categories` query and show
  category NAMES covering both system rows and the caller's own custom rows; the
  submitted payload carries the selected row's `category_id`. No UUID-shaped
  text input remains. Negative control: an option list built from a fixture with
  two categories must render both names and submit the right id.
- **ac2 - edit prefills.** When the form is opened to edit an existing expense,
  the select is preselected to that expense's `category_id` (the merged
  `initialValues(expense)` path), and a failed submit preserves the selection
  (the REQ-FE-082 values-preserved leg, replacing the old input-value assertion).
- **ac3 - the empty and no-suitable-category paths.** An unset category still
  produces the existing validation error, and the form offers a hint pointing at
  the Categories page when no suitable category is available (the merged
  categories surface is where a custom category is created). The hint must not
  invent a route: `/categories` is the merged route nested under the app shell.
- **ac4 - pin disposition is explicit and measured.** The three pinned
  call-sites above are listed in the card with the new assertion that replaces
  each; the card records the command it ran (`npx vitest run` over the touched
  test files from `frontend/`, and the affected e2e spec) and the measured
  before/after. No pin is deleted without a named replacement assertion.
- **ac5 - delta purity.** Only the allow-listed files differ; backend, API,
  database, seed data, README and `docs/` are byte-unchanged; the shared MSW
  fixture is unchanged unless the card names why.
