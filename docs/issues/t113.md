## Goal

Three dimensions decide whether the project is real: does the full stack run end to
end with a single command, do unit AND integration tests run with a single command and
pass, and does the whole system including the database come up through
Docker/Compose with a single command. This card records, for each, the claim, the
measured reason, ONE 30-second entry point, and the paths a grader opens next.

**Honesty rule (binding): a claim is allowed only if a reader can check it within 30
seconds at the named entry point.** Where a claim depends on running something, the
entry point is the command or the file that shows the command, and the reason line
names the measurement this card actually took. No score is invented.

## Survey recon (anchors the record may cite; groom re-measures)

- **Application:** `README.md` `## Quick Start` step 4 `npm run dev` (backend
  :8000 + frontend :5173); root `package.json` scripts; seeded demo path
  `npm run seed:demo` -> `backend/app/scripts/seed_demo.py`.
- **Testing:** `backend/tests/unit/` and `backend/tests/integration/` (uv run pytest),
  frontend vitest (`frontend/package.json`), CI in `.github/workflows/ci.yml`
  (measured at survey: `push: [main]` + `pull_request` triggers, backend ruff/mypy/
  unit/integration jobs and a frontend job). The single-command local surface is the
  root `package.json` test scripts / `make` targets, which is what REQ-TEST-051
  parity requires.
- **Containerization:** `Dockerfile`, `docker-compose.yml`, README
  `## Local verification in five minutes` (the `cp .env.example .env` +
  `docker compose up --build` block, REQ-DOC-071 mandated).
- Leg numbering: 0-based indexes into `tests` of `docs/state/merge_test_index.json`.
- Environment honesty: `docker` and a listening dev server may be unavailable in the
  verification environment. Where a claim cannot be executed in the environment, the
  record states the entry point (the file that defines the single command) and the
  reason names the strongest evidence that IS checkable there (e.g. the stored merge
  gates that execute the compose build, or CI). The record must not assert a number of
  tests it did not run.
