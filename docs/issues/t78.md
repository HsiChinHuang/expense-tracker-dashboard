**The named mechanism (this is the sentence the card promises and ac3 proves).**
`/metrics` is local-only by an **in-process loopback gate on the direct ASGI
peer**: the route handler resolves `request.client.host` with `ipaddress` and
serves the exposition only when `is_loopback` is true (`127.0.0.1` and `::1`);
every other peer gets a `404` indistinguishable from an unknown path, and
`X-Forwarded-For` is never consulted. In addition the route is **mounted only
when `get_settings().ENVIRONMENT` is `development`**, read at `create_app()`
time, so a production-configured app does not carry the route at all. The two
are not alternatives: the environment gate is the deployment-side fact and the
peer gate is the runtime fact, and the peer gate is the strictly stronger of
the two because it holds even inside a development container bound to
`0.0.0.0:8000` (which is what the frozen `Dockerfile` CMD does).

**The three pinned resource-attribute values** (values are pinned by this card;
metric NAMES are not):

| Resource key | Pinned value | Source of the value |
|---|---|---|
| `service.name` | `expense-tracker-api` | the `SERVICE_NAME` module constant in `telemetry.py` (a literal, not a setting) |
| `deployment.environment` | `get_settings().ENVIRONMENT` (default `development`) | `backend/app/config.py:42` |
| `service.version` | `get_settings().APP_VERSION` (`1.0.0`) | `backend/app/config.py:43` |

Prometheus renders these as `target_info{service_name="expense-tracker-api",
deployment_environment="development", service_version="1.0.0"}` (dots become
underscores; `target_info` appears only once at least one instrument exists -
measured in the probe venv - which is why ac2 requires a live sample line and
not merely a 200).

**Why idempotency is a requirement, not a nicety.** `create_app()` runs once at
import (`app = create_app()`) and again per test application, and
`set_meter_provider()` on a second call emits
`Overriding of current MeterProvider is not allowed` through the `logging`
module (measured: NOT through `warnings`, so a `-W error` leg would not catch
it) while silently keeping the first provider - possibly a test provider.
`setup_telemetry()` therefore guards with
`isinstance(metrics.get_meter_provider(), MeterProvider)` BEFORE constructing
anything, and ac1's fence fails on that exact warning string in the pytest
output.
