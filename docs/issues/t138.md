### ac_hash extraction recipe (ANCHORED - the t135 lesson, WAL 1372 gate A)

The hash is sha256 over `json.dumps(blocks, separators=(',',':'))` of the six fenced `bash`
blocks under `## Acceptance criteria`, each block CR-stripped and `strip()`-ed, in document
order. Extraction MUST be anchored at column 0 - a naive non-anchored fence regex truncates any
block containing an inline backtick fence pattern (the t135 ac3 failure):

```python
import hashlib, json, re, subprocess
blob = subprocess.run(["git", "show", "<card commit>:docs/issues/t138.md"],
                      capture_output=True).stdout.decode("utf-8", "replace")
t = blob.replace("\r\n", "\n")
sec = re.search(r"(?m)^## Acceptance criteria[ \t]*$\n(.*?)(?=^## )", t, re.S)
blocks = [b.replace("\r\n", "\n").strip()
          for b in re.findall(r"(?m)^```bash[^\n]*\n(.*?)^```[ \t]*$", sec.group(1), re.S)]
assert len(blocks) == 6, len(blocks)
print(hashlib.sha256(json.dumps(blocks, separators=(",", ":")).encode()).hexdigest())
```

This recipe is the same one t136 published and the verifier re-derived successfully
(`b8c99f9a...` MATCH at WAL 1382); it discriminates (t135's known-bad literal test in t136's card).

## Goal

`backend/scripts/docs_verification.py` `check_links()` (:313-318) walks the FILE SYSTEM with
`os.walk` and filters only by the hardcoded `SKIP_DIRS` set (:96). `os.walk` knows neither git
tracking nor `.gitignore`, so ANY untracked/gitignored `.md` file outside `SKIP_DIRS` silently
enters the `LINK_CHECK files=` counter and the link scan. Same commit, two answers,
machine-dependent - the exact contamination class behind the REJECTED t136 digest
`4b1ec8a1...` (files=320 links=94) and the stray-`nul` incident.

The fix: derive the `.md` set from git (`git ls-files "*.md"` over `ROOT`) - the set the tree
RECORDS - so the counter is machine-independent BY CONSTRUCTION. This is t136's M4.

### The git-invocation contract (measured on THIS host; the builder must honor it)

| Invocation | In a plain clone | In a pi-subagent WORKTREE (`.git` file points at a Windows path) |
|---|---|---|
| `git ls-files *.md` (direct, `cwd=ROOT`) | rc=0, 306 lines | **rc=128** `not a git repository: /mnt/c/.../C:/Users/...` |
| `cmd.exe /d /c "git -C <wslpath -w ROOT> ls-files *.md"` (UNQUOTED glob) | rc=0, 306 lines | rc=0, 306 lines |
| `cmd.exe ... ls-files \"*.md\"` (QUOTED glob) | rc=0, **0 lines** | rc=0, **0 lines** - vacuous-zero trap, forbidden |

So the generator must try direct git FIRST, the `cmd.exe`+`wslpath -w` form SECOND (this covers
WSL worktrees - the harness this repo's own fences run in), treat empty output as unusable, and
never fall back to the walk. (The `wslpath`/`cmd.exe` binaries being absent on a native box is
covered by the same rule: OSError -> attempt fails -> direct git answers.)
