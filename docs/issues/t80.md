## Goal

Create the `incident-response/` carrier directory and the ONE mechanism that
turns criterion 13's static worked example into measured evidence: a collector
script that, given an incident ID, captures the four artifacts an on-call
engineer would ask for - the health payload, a `/metrics` snapshot, a backend
log tail and the deployed version - into `incidents/<ID>/evidence/`, and that
can also PRODUCE a degraded state on demand (`--simulate-fallback`) so the
evidence is measured rather than attested-by-reference.

## AC draft (groom will fence these - target 5 fenced ACs, inside max_acs=6)

- **ac1 - the collector exists, is bash-clean, and refuses to guess.**
  `incident-response/collect-evidence.sh` exists, passes `bash -n`, takes an
  incident ID and an optional base URL, writes into
  `incidents/<ID>/evidence/`, and exits non-zero with a readable message when
  the ID is missing or the endpoint is unreachable (no silently empty
  bundle). Negative control: an empty ID must exit non-zero.
- **ac2 - the four artifact legs are named and each writes its own file.**
  health payload, `/metrics` snapshot, backend log tail, deployed version
  (commit SHA + `git describe`-style string) each land as a separate named
  file plus a manifest that records which legs produced bytes and which were
  recorded as unavailable. The fence proves the four leg NAMES are present and
  that the manifest schema is fixed - it does not require a live server (that
  leg is ac3/ac4 and t84's real run).
- **ac3 - `--simulate-fallback` produces a genuinely degraded state and
  restores afterwards.** The mode points `DATABASE_URL` at a dead PostgreSQL
  endpoint, restarts the local uvicorn on the caller-supplied port, waits for
  health, captures the degraded evidence, and then RESTORES the original
  `DATABASE_URL` / process state (kill the child it started, restore the
  environment, remove its scratch files). The fence proves the mode exists,
  that the dead-DSN it uses is a LOOPBACK dead port (never a remote host), and
  that the restore step is unconditional (a trap on EXIT), by static
  inspection of the script plus a dry-run leg that starts nothing.
- **ac4 - the evidence bundle is machine-readable and self-describing.** The
  manifest carries incident id, collected-at timestamp, endpoint, the four leg
  statuses and the tree hash, so t84's `evidence.json` is this file's
  measured content rather than a hand-written restatement. The fence validates
  the manifest shape with a self-contained parser leg.
- **ac5 - delta purity and the read-only boundary.** Only
  `incident-response/collect-evidence.sh` and `incident-response/README.md`
  are added; `backend/`, `ops/`, `security/`, `openapi.yaml`, `README.md`,
  `docker-compose.yml` and every `docs/` file are byte-clean against the
  immutable ref named in the card; the script contains no write call against
  the database, no `DROP`/`UPDATE`/`DELETE`, no merge command and no
  production host (grep-enforced), which is the same boundary t82's policy
  states in declarative form.

## Constraints (hard)

- Exactly 2 files: `incident-response/collect-evidence.sh`,
  `incident-response/README.md`. `incidents/` is t83's directory;
  `responder-task.md` / `response.schema.json` are t81's;
  `autonomy-policy.yaml` / `runbooks/` are t82's. Creating them here is a card
  FAIL.
- Read-only against the product: the collector NEVER mutates the database,
  never edits a file under `backend/`, never restarts anything it was not
  asked to restart, and never touches Docker or a production host. The only
  process it may start or stop is the local uvicorn child it spawned itself,
  in `--simulate-fallback` mode, on a port the caller passed.
- The dead PostgreSQL target used by `--simulate-fallback` MUST be a loopback
  address on a port nothing listens on, chosen and documented by the card. It
  must never be a remote host and never the compose `db` service (that would
  make the drill depend on Docker, which no gate in this milestone may do).
- Local endpoints only: default base URL is the pinned
  `http://127.0.0.1:8137/api/v1`; the script must not contact any non-loopback
  address (the coding-standards forbidden-actions table forbids curl to
  non-Platform APIs).
- Evidence files are UTF-8 text, LF, no secrets: the script must not capture
  `.env`, `JWT_SECRET`, tokens or password values into the bundle, and the
  README states that rule where a reviewer can see it.
- Windows/WSL reality: the script is bash (it runs under the same WSL bash
  the merged gates use) and every git/npm/npx call inside it goes through
  `cmd.exe /d /c "..."` with no `/dev/null` redirection; the card records that
  the builder measured the script on this machine, not on an imagined Linux CI.
- No dependency additions; no backend/API/DB/contract change;
  `openapi.yaml` untouched.
