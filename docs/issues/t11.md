## Goal

Deliver the categories backend vertical on the merged t8 router/service
pattern: Pydantic category schemas, `category_service` (list/create/delete +
the `validate_category_access` helper), and the three endpoints
`GET/POST /api/v1/categories`, `DELETE /api/v1/categories/{id}` registered
under `/api/v1` in `create_app()` after health+auth. System categories are
read-only to every user; custom categories are visible and mutable only to
their owner; deletion is blocked while expenses reference the category (the
FK RESTRICT is t13's table, so this issue enforces the 409 at the service
layer with an explicit count check — groom pins how the in-use check is
tested before the expenses table exists, e.g. by inserting category-referencing
rows only after t13, or by a service-level unit test with a stubbed query).

## Acceptance criteria

- [ ] ac1 — `GET /api/v1/categories` (authenticated) returns 200 with the ten system categories plus only the caller's own custom categories (never another user's), each body carrying the public fields (id, name, color, icon, is_system); unauthenticated returns 401 via merged `get_current_user` behavior (REQ-API-030, REQ-SEC-030).
- [ ] ac2 — `POST /api/v1/categories` with `{name, color, icon?}` returns 201 with `is_system=false`, `user_id` = caller; 409 (`code` per merged error-code taxonomy, `field="name"`) on duplicate against the caller's own categories or against a system category name (REQ-PROD-034); 422 `VALIDATION_ERROR` for invalid HEX color, name > 100 chars, or missing fields, bodies `{detail, code, field}` (REQ-API-031, REQ-DB-021/023).
- [ ] ac3 — `DELETE /api/v1/categories/{id}` returns 204 for the caller's own unused custom category; 404 for unknown id, another user's category, AND for a system category (system categories are not deletable — REQ-SEC-033; groom pins 404-vs-409 mapping against Chapter 7 §7.4.3 before implementation); 409 when the category is referenced by expenses (REQ-API-032). No update endpoint for categories exists at all (system-category immutability by absence, REQ-PROD-034).
- [ ] ac4 — `validate_category_access(db, user, category_id)` in the service layer returns the category iff `is_system OR user_id == user.id`, else raises the not-found AppError (REQ-BE-063, REQ-SEC-032); unit tests cover system / own / other-user / unknown cases. This helper is the contract t13 consumes.
- [ ] ac5 — No regression and quality gates: full `uv run pytest` green (merged suite + new category tests), `ruff check .` and strict `mypy .` exit 0; routers registered so `/openapi.json` lists the three category paths after health/auth paths.
