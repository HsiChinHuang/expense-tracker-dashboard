## Goal

Deliver the categories backend vertical on the merged t8 router/service
pattern: Pydantic category schemas, `category_service` (list/create/delete +
the `validate_category_access` helper), and the three endpoints
`GET/POST /api/v1/categories`, `DELETE /api/v1/categories/{id}` registered
under `/api/v1` in `create_app()` after health+auth. System categories are
read-only to every user; custom categories are visible and mutable only to
their owner; deletion is blocked while expenses reference the category.
The expenses table arrives with t13, so this issue enforces the 409 at the
service layer with an explicit expense-count query whose counting function
is monkeypatched in a service-level unit test (review_plan W3 ruling — see
ac3 and Context); t15 re-proves the same path end-to-end after t13 merges.

- **W4 (name > 100 → 422 layer) — RESOLVED: Pydantic schema layer.**

  (Chapter 7 §7.4.2's CreateCategoryRequest bounds verbatim); the 422 test
  exercises it through POST. The Builder must NOT add a DB CHECK for name
  length — REQ-DB-021 defines only the HEX and system-consistency CHECKs and
  SQLite would not enforce VARCHAR(100) anyway.

Contract pins taken verbatim from Chapter 7 §7.4 (the REQs are terse; the
chapter is the tie-break):

- GET 200 body is the **object wrapper** `{"categories": [...]}` (NOT a bare
  array); `CategoryResponse` required keys are exactly
  `{id, name, color, icon, is_system, created_at}` — `user_id` is never
  exposed.
- POST body is `{name (1-100 chars), color (HEX pattern), icon? (≤50 chars)}`;
  201 returns the same `CategoryResponse` shape.
- DELETE: 204/404/409 only; path param is the category uuid.
- Ordering per REQ-BE-060 / Chapter 6 §6.7.1: `is_system DESC, name` —
  system block first, each block alphabetical.
- Duplicate check per REQ-BE-061 / §6.7.2: **case-insensitive** within the
  caller's own categories, and (REQ-PROD-034) against system names too.
  Error: 409 `DUPLICATE_CATEGORY`, `field="name"`.
- Access validator per §6.7.4: returns the category iff `is_system OR
  user_id == user.id`, else 404 `CATEGORY_NOT_FOUND` (field `category_id`)
  — 404 not 403, to avoid revealing existence (REQ-BE-063/REQ-SEC-032).
- Delete of another user's category → 404 `NOT_FOUND` per §6.7.3's reference
  (`NOT_FOUND`, field None); system delete → 404 per W2 (pinned as
  `CATEGORY_NOT_FOUND` — both are 404; the code follows §6.7.4's "missing or
  not owned" taxonomy and t13 consumes the same helper).

## Isolation contract

- Every pytest-backed test builds its own SQLite file under pytest's
  `tmp_path` (one file PER TEST, named after the test). Reading
  `os.environ["DATABASE_URL"]` inside the new modules is FORBIDDEN (t8
  precedent): ac2 runs four nodes and ac3 runs four+two nodes in ONE pytest
  process; a shared injected file makes them collide.
- Schema build is `Base.metadata.create_all` (NOT alembic); system
  categories are provisioned per test by calling
  `seed_system_categories(connection)` — the same function the 002 data step
  calls — with an explicit commit, mirroring `tests/unit/test_category_seed.py`.
- App isolation is `application.dependency_overrides[get_db]` over
  `create_db_engine`/`create_session_factory`; mutate/assert rows with
  `with next(override()) as session:` (the override is a generator function).
- The `DATABASE_URL="sqlite:////tmp/t11_acN.db"` pin is a rail for anything
  reading app settings; each command `rm -f`s its files. `backend/dev.db` is
  unreachable from all five commands.
- JWT settings are pinned per test module exactly as t8's
  `_pin_jwt_settings` autouse fixture does (with `get_settings.cache_clear()`
  on setup AND teardown).

## Builder traps (probed against merged main)

1. `delete_category` must NOT import `Expense` at module top — `app.models.expense`
   does not exist until t13; the count lives in `count_expenses_for_category()`
   with the import inside the function body (W3 seam; the pinned unit test
   monkeypatches this exact name, so renaming it breaks the contract).
2. GET must return the `{"categories": [...]}` wrapper (Chapter 7 §7.4.1) — a
   bare array satisfies nothing and breaks t16's mirrored type.
3. 204 responses must have empty bodies; `TestClient` asserts `response.content == b""`.
4. Path param name is `category_id` (Appendix B's field pin + §7.4.3); the
   response model must exclude `user_id` (exact six-key assertion in tests).
5. `field` for the duplicate 409 is `"name"`; for the in-use 409 Appendix B
   says `category_id` — pin `field="category_id"` there (the delete path param
   is `category_id`, so it is consistent).
6. FastAPI 0.142 `app.routes` contains `_IncludedRouter` objects without
   `.path` — assert routes via `app.openapi()["paths"]` (key order preserved;
   t8 trap #5 still holds).
7. The 422 handler already maps `RequestValidationError` → `{detail, code, field}`;
   do not add a second validation layer in the service for color/name-length —
   Pydantic owns them (W4). Service-side duplicate check is DB-query based.
8. `name.strip()` before persisting (Chapter 6 §6.7.2); duplicate comparison
   uses `func.lower(Category.name) == name.lower()`.
9. Commit discipline: service functions own `db.commit()` (t8 auth_service
   pattern); the router stays thin.
10. mypy strict: the lazy-import function returns `int`; a `cast` of an
    already-correct type is a redundant-cast error.
