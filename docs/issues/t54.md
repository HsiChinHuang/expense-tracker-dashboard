## Context

The E2E GitHub Actions workflow has NEVER passed in repository history
(standing gate platform #45). First real run 38284562729 on 91b528e:
steps 1-7 SUCCESS (the t47 health-wait fix works live), step 8

`browserType.launch: Executable doesn't exist at

**Measured root cause (job log 114930218630, retrieved at groom - NOTE:
the direction is the OPPOSITE of the survey prose, which swapped the two
build numbers):**

- `.github/workflows/e2e.yml` "Install Playwright browsers" runs
  `npx playwright install --with-deps` at the REPO ROOT. The root tree
  has NO playwright dependency, so npx printed
  `npm warn exec The following package was not found and will be installed:
  playwright@1.64.0` (job log line for step 7) and DOWNLOADED browser
  build **v1248** ("playwright chromium v1248" / "chromium-headless-shell
  v1248" downloaded to ~/.cache/ms-playwright/chromium-1248 and
  chromium_headless_shell-1248).
- `make e2e` runs in `e2e/` with the PINNED `@playwright/test 1.58.0`
  (e2e/package.json, REQ-TECH-075). Measured locally at groom:
  `npm install --no-save` in a copy of e2e/ then
  `playwright-core/browsers.json` pins chromium and chromium-headless-shell
  at revision **1208** - so step 8 launches 1208, which step 7 never
  installed. Hence the exact error above.
- Registry cross-check at groom: playwright-core@1.64.0 browsers.json
  pins 1248; 1.58.0 pins 1208. The mismatch is a version-pairing defect,
  not a missing-cache defect.

**The fix (one run line in one file):** run the install FROM the e2e
workspace after installing the pinned package:
`cd e2e && npm install --no-save && npx playwright install --with-deps`.
The `npm install --no-save` prefix mirrors the W6 no-lockfile recipe
already used by `make e2e` (the e2e lockfile is NOT committed) and is
REQUIRED: `npx` prefers the local `e2e/node_modules/.bin/playwright`
(1.58.0, verified locally at groom: `npx playwright --version` = 1.58.0
after the install), so the install command downloads exactly build 1208
that the harness launches. Step order, the ms-playwright cache step, the
make e2e invocation and every other byte of the workflow stay untouched.
