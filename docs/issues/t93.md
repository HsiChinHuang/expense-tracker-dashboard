## Goal

The live deployment is real, but the `security_ops` verifier still records it as
a deferral whose reason is "the live URL returns 404, measured". That sentence
was true and is now false, and a register that lists a satisfied item as
deferred is a defect of the same class as a fabricated PASS. This card moves
exactly one row - `LIVE_DEPLOYMENT_STATE` - from DEFERRED to VERIFIED, moves the
URL constant it is built from to the host that actually answers, and re-premises
the one gate (tests[187]) that pins both the count and the old row text. It
replaces the deleted deferral with a *stronger* verified-row assertion (live
health 200 + `database=postgresql` + `fallback_active false`), so the register
still lists every genuinely unverifiable row and the moved row is protected by
something, not merely deleted.
