## Goal

Wire the complete backend auth vertical: Pydantic auth schemas, an auth service
(register/login with the timing-safe and lowercase-email rules), the
`get_current_user` FastAPI dependency, the `{detail, code, field}` error
infrastructure, and the three endpoints `POST /api/v1/auth/register`,
`POST /api/v1/auth/login`, `GET /api/v1/auth/me` registered under `/api/v1` in
`create_app()` (health first, auth second). After this issue a real user can
obtain and use a 24-hour JWT against the SQLite dev database; t9 consumes these
endpoints on the frontend.

## Context

- **Why this issue exists.** phase_2_auth's vertical: t5 gave settings and the
  session plumbing, t6 the `users` table, t7 the bcrypt and JWT primitives. t8
  is the first issue that turns those primitives into an HTTP surface a user can
  hit, and it is the last backend issue before t9 (frontend auth) — t9's axios
  client and `AuthContext` are written against exactly these three paths and
  this error shape.
- **Merged reality this groom was written against (main @ a39d697, re-verified
  on-tree).** `app/config.py` exposes `DATABASE_URL`/`JWT_*` through a
  `lru_cache`d `get_settings()` (isolation lever: `monkeypatch.setenv` +
  `get_settings.cache_clear()`, plus a second clear on teardown — t7 precedent).
  `app/database.py` exposes `create_db_engine` / `create_session_factory` /
  `get_db`. `app/models/user.py` exposes `Base` + `User` (Python-side UUID pk,
  `hashed_password`, `is_active`, `created_at`). `app/auth/password.py` exposes
  `hash_password` / `verify_password` (catches `UnknownHashError` only) /
  `verify_dummy`; `app/auth/jwt.py` exposes `TokenError` /
  `create_access_token(subject: str) -> str` / `decode_access_token` (raises
  `TokenError`). `app/main.py` currently registers only the health router and
  there is **no** error-handling infrastructure yet: `app/core/` is an empty
  package and no `AppError` exists anywhere on main.
