Groom measured the FULL defect chain on a daemon-free local stack (ext4
staging: real vite dev server on 127.0.0.1:5173 with the merged t51/t55

a card that fixes only line 23 dies on the next line, so this card fixes
the whole chain (measured: base RED 3 failed -> fixture GREEN 3 passed):

1. helpers.ts:23 `getByLabel('Password')` is a SUBSTRING match in strict
   mode and hits BOTH `#register-password` (label `Password`) and
   `#register-confirm-password` (label `Confirm password`) on /register.
   Fix: `getByLabel('Password', { exact: true })` plus
   `getByLabel('Confirm password')` for the confirm field.
2. `POST /auth/register` 201 returns UserResponse (REQ-API-020, openapi
   byte-pinned) with NO `access_token`, but frontend
   `auth_context.register()` persists `result.access_token` (REQ-FE-061
   auto-login assumption) -> the session never exists and register never
   redirects. Fix: frontend fallback - when the response carries no token,
   immediately `loginApi({email, password})` with the just-registered
   credentials (REQ-FE-061 auto-login semantics, no openapi change).
3. helpers.ts used the FICTIONAL `page.requestGet(...)` - the real API is
   `page.request.get`. The t27 d.ts gate (tests[140]) type-checked it only
   because `e2e-gate-types.d.ts` declared the fictional method. Fix: call
   `page.request.get` and declare `request: { get(...) }` in the d.ts; the
   d.ts getByLabel/getByRole signatures gain the `exact?: boolean` option
   the real 1.58.0 API supports (verified against the hermetic d.ts).
4. The specs used category names `Food` / `Transport`; the seeded system
   rows are `Food & Dining` / `Transportation` (t10) - `resolveCategoryId`
   threw `category not found`. Fix: the real names in all three specs.
5. `getByRole('heading', { name: 'Budget' })` (setBudget helper) resolves
   to 3 elements on /budgets (heading `Budget` + `Budget progress` +
   `Budget usage` text). Fix: `{ exact: true }`.
6. isolation.spec read `kpi-total` right after addExpense without a
   navigation - the dashboard KPI had not refetched. Fix: `pageA.goto('/')`
   before the assertion (the spec's own month-switch sibling already does).
7. `loginUser` timed out when the caller was already authenticated: /login
   redirects to / so the form never appears. Fix: check
   `window.localStorage.getItem('token')` first and skip the form-fill when
   a session exists.

   $440.25), edit 12.50->22.50 => $59.75... measured $65.00 because
