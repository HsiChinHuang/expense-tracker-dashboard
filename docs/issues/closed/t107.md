**The stamp format (the deliverable contract).** A stamped findings record carries a
top-level `index_stamp` object with at least: `path` (the index path), `git_blob_id`
(the git blob object id - sha1 over `blob <N>\0` plus the CR-normalized (CRLF->LF)
index bytes, computed with hashlib so the AUDITOR needs no git subprocess and stays
stdlib-only/offline/read-only), `sha256_cr_normalized`, `bytes_cr_normalized`,
`normalization` (the statement that CRLF is folded to LF before hashing, so a
`core.autocrlf=true` worktree and the stored blob agree - measured: worktree 1,305,554
raw bytes vs 1,304,097 normalized), and optional `provenance_commit`. The record also
carries a `replay_contract` string stating that the record is a snapshot of the
STAMPED index blob, that a replay against a DIFFERENT blob is expected to mismatch,
and that `--against-record` is the instrument that classifies such mismatches.

**The `--against-record PATH` contract (auditor).** Read-only, stdlib-only, offline;
it never changes the existing scan/print/exit contract when the flag is absent. With
the flag, after the normal scan of `--index`:
- record has NO `index_stamp` -> print an UNSTAMPED note naming the record, exit 0
  (a legacy record cannot be classified; saying so honestly beats guessing);
- stamp == scanned index blob -> compare the record's per-path observations to the
  fresh ones: all agree -> print EXPECTED lines and exit 0; any disagreement ->
  print DRIFT lines naming leg/issue/ac/path/record-vs-fresh AND the
  `AGAINST-RECORD GATE` line, exit 1 (same-blob disagreement is real drift, the
  only nonzero path the cross-check has, besides the existing 2 for an unreadable
  index);
- stamp != scanned index blob -> cross-blob replay: observation differences are
  classified EXPECTED (stamp mismatch) and printed as such with a count, exit 0 -
  the record was never a claim about THIS index;
- `--expect-pins` keeps its t106 semantics unchanged.
