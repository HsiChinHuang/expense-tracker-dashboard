## Context

Why this card exists: **the E2E workflow has never succeeded in the repository's entire history.** CI run evidence: GitHub Actions run `12833892326`, job `E2E`, **conclusion FAILURE** - the app container starts, `uv run alembic upgrade head` raises `ModuleNotFoundError: No module named 'psycopg'`, the container exits, port 8000 never listens, and the wait step dies with `curl: (56) Recv failure` then 29x `curl: (7) connection refused` ("health endpoint never turned ok"). Workflow history over the full range: 71 failures + 1 cancelled, **zero successes**.

Root cause (orchestrator-measured on MAIN after the t42 merge): `docker-compose.yml:32` sets `DATABASE_URL: postgresql+psycopg://...`, the Dockerfile installs the runtime set with `uv sync --frozen --no-dev` (line 38), but **neither `backend/pyproject.toml` nor `backend/uv.lock` mentions psycopg anywhere** (`grep -c psycopg` == 0 in both). SQLAlchemy 2.x resolves the `+psycopg` dialect lazily, so the failure surfaces only at container start. The driver is the single missing link in the install path.

The second, measured defect is in the fallback that was supposed to survive it: `backend/app/database.py` wraps **only** `create_engine(...)` in `try/except (SQLAlchemyError, OSError, ImportError)`. `create_engine` does not import the DBAPI driver (lazy resolution), so a missing driver raises at the first `.connect()` - **outside** that `try` - and the REQ-BE-130 SQLite fallback never engages. The card therefore repairs both the driver (first cause) and the fallback semantics (second cause), and adds an auditable, offline-safe connect probe.

Plan/design pointers: `docs/plan.md` phase_5_infra (t24 compose stack, t26/t27 workflows), `docs/issues/closed/t42.md` (the CI/E2E repair this card continues), `docs/requirements.md` REQ-BE-130/133, FR-DB-1.
