## Goal

Two dimensions decide whether the project ships: is it deployed at a public URL with a
clear demo (0-2), and does CI/CD exist (0-3, where 1 = tests on PR, 2 = plus automatic
CD, 3 = plus CD to dev AND a manual production deploy). This card records the honest
position on both.

The CI/CD dimension is where a map can most easily lie, because the difference between
2 and 3 is a second environment. The operator's chosen strategy is "stable 2 + fight
for 3": **claim 2/3 with the gap priced in one sentence**, and ship the real
human-gated manual deploy pipeline in-repo (t119's `promote.yml`). The record must
state both facts plainly:

- the human gate **DOES exist** - GitHub Environment `production` with required
  reviewers, created by the operator in repo Settings (not in git), consumed by
  `promote.yml` via `environment: production`; and
- environment separation **DOES NOT exist** - there is no second Render service, no
  dev instance, no separate database; the promote pipeline targets the SAME live
  service the auto-CD already deploys.

**Honesty rule (binding): a claim is allowed only if a reader can check it within 30

line. No score is invented, and the record does not describe `promote.yml` as if a
