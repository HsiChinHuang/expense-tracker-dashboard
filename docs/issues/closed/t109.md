## Context

**The measured hosted defect (D1).** The hosted app at
`https://expense-tracker-dashboard-1qtu.onrender.com` (deployed from main tip
`cd0bf50`; the product bytes have been identical to `backend/`, `frontend/` and
`Dockerfile` since `6addba0`) serves the correct HTML shell for `/login` and
`/index.html` and renders a BLANK PAGE, because every asset that shell references
404s. Measured on the live host:

- `GET /assets/index-DpxkfWRY.js` -> 404 `application/json` `{"detail":"Not Found"}`
- `GET /assets/assets/index-DpxkfWRY.js` -> 200 `text/javascript`, 772815 bytes

The second URL is the giveaway. `Dockerfile` line 46 runs
`COPY --from=frontend-build /app/frontend/dist ./static`, so the image lands the
Vite `dist/` layout - `index.html` at the ROOT plus every hashed bundle below
`assets/` - inside `backend/static`. `register_spa_static` then mounts
`StaticFiles(directory=static_dir, html=True)` at `SPA_MOUNT_PATH = "/assets"` where
`static_dir` is that WHOLE copied dist. So the URL `/assets/<hashed>.js` resolves to
`backend/static/<hashed>.js`, while the file lives at
`backend/static/assets/<hashed>.js`. **The mount POINT is correct; the mounted
DIRECTORY is one level too high.** The fix is to mount the directory the bundles
actually live in.

**Why the green pipeline missed it (a design gap, not a broken pipeline).** Four
independent facts each held, and together they made the deployment blind:

1. `backend/tests/unit/test_static_serving.py`'s `_build_static` fixture wrote its
   asset at `static_dir/app.js` - the directory ROOT. The too-high mount and the
   fixture agreed, so `GET /assets/app.js` -> 200 passed HONESTLY against a FALSE
   PREMISE. The test did its job; the fixture invented a layout the shipped image
   never produces. This is the part this card repairs.
2. The E2E suite runs the Vite DEV server on :5173 and never traverses the
   single-container static path at all.
3. All six hosted legs in the merge index (t26, t41, t57, t58, t59, t70) probe
   `/api/v1/health` and README text. NONE fetches a frontend asset.
4. The frozen static-serving leg (0-based index 130, t24) greps
   `SPA_MOUNT_PATH == "/assets"`, which stays TRUE after this fix. The frozen
   literal is not the bug, and leg 130 is not the thing to change.

**The fix (contract, not implementation).** Inside `register_spa_static`, mount
`static_dir / SPA_ASSET_SUBDIR` (a new module-level constant, `"assets"`) at the
frozen `SPA_MOUNT_PATH`. The signature, the frozen call site, the gate and the
catch-all's resolution against the OUTER `static_dir` all stay as they are: the
catch-all must keep resolving `index.html` at the dist root, which is where Vite
puts it. `SPA_ASSET_SUBDIR` is deliberately NOT added to the frozen-literal set -
this card introduces it.

**STRICT, WITH NO FLAT-REPO FALLBACK (recorded decision).** The mount target is
`static_dir/assets` unconditionally. A tree with `index.html` at the static root but
NO `assets/` subdirectory makes `StaticFiles` raise at startup and the container
refuses to boot. That is chosen deliberately over the alternative: a fallback that
re-mounts at the outer directory reproduces the exact silent blank-page failure this
card exists to remove, and a deployment that cannot serve its own bundles has no
correct second behaviour - a crash loop with a traceback in the host log beats a
200-with-blank-page. The failure mode is recorded as a residual risk, and the
gate (`if index_file.is_file():`) is unchanged so the committed route-free tree
never touches this path.

**Fixture re-shape is legal and required.** Leg 130 runs the three pytest node IDs
BY NAME and only does `test -f` on the file; the file's CONTENT is not frozen. The
re-shaped `_build_static` stages `index.html` at the static root with the asset
below `assets/`, mirroring `frontend/dist`. The frozen node IDs then pass only
against a mount that resolves the inner directory - so the guard against this defect
CLASS becomes permanently live in the merge sweep with ZERO index bytes.
