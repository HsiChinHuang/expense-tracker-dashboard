## Goal

Initialize the Vite + React + TypeScript frontend under `frontend/` with
Tailwind, Router, TanStack Query, Axios, and a Vitest/RTL test harness, plus a
minimal app shell, so install, test, and type-check all succeed. Tooling
skeleton only: no feature pages, no forms, no charts, no API data flow.

## Verification commands

Environment note (Builder and Verifier): node/npm are Windows binaries and
`npx tsx`/node tooling fails when invoked from WSL paths. Every command below
is self-contained: it derives the Windows path of `frontend/` via
`wslpath -w "$PWD/frontend"` and runs the toolchain through
`cmd.exe /c "cd /d <winpath> && <tool command>"`. Run all commands from the
repository root in WSL bash. Commands ac2/ac4/ac5 assume `npm install`
(ac2) has been run first, as they need `node_modules`.

- ac1: `bash -c 'test -f frontend/package.json && node -e "const fs=require(\"fs\");const p=JSON.parse(fs.readFileSync(\"./frontend/package.json\",\"utf8\"));const d=Object.assign({},p.dependencies,p.devDependencies);const r=[\"react\",\"react-dom\",\"react-router-dom\",\"@tanstack/react-query\",\"axios\",\"tailwindcss\",\"vitest\",\"@testing-library/react\",\"msw\",\"eslint\",\"prettier\",\"typescript\"];const b=r.filter(k=>!d[k]||!/^[0-9]/.test(d[k]));if(b.length){console.error(\"unpinned or missing: \"+b.join(\", \"));process.exit(1)}" && git ls-files --error-unmatch frontend/package-lock.json >/dev/null'`
- ac2: `bash -c 'test -f frontend/package.json && D=$(wslpath -w "$PWD/frontend") && cmd.exe /c "cd /d $D && npm install --no-audit --no-fund" >/dev/null'`
- ac3: `bash -c 'test -f frontend/src/main.tsx && grep -q createRoot frontend/src/main.tsx && grep -q "id=\"root\"" frontend/index.html && ls frontend/tailwind.config.* >/dev/null && grep -RqE "@tailwind (base|components|utilities)" frontend/src --include=*.css && grep -RqE "className=\"[^\"]*(flex|grid|min-h-screen|mx-auto|p-[0-9]|text-[a-z])" frontend/src --include=*.tsx'`
- ac4: `bash -c 'test -f frontend/package.json && find frontend/src -name "*.test.tsx" | grep -q . && D=$(wslpath -w "$PWD/frontend") && cmd.exe /c "cd /d $D && npm test -- --run" >/dev/null'`
- ac5: `bash -c 'test -f frontend/tsconfig.json && D=$(wslpath -w "$PWD/frontend") && cmd.exe /c "cd /d $D && npx tsc --noEmit"'`
- ac6: `bash -c 'test -f frontend/package.json && node -e "const fs=require(\"fs\");const p=JSON.parse(fs.readFileSync(\"./frontend/package.json\",\"utf8\"));const d=Object.assign({},p.dependencies,p.devDependencies);const bad=Object.keys(d).filter(k=>/^(styled-components|@emotion\/|styled-jsx|@stitches\/|@linaria\/|react-native-css)/.test(k)||/^(react-hook-form|zod|recharts|date-fns)$/.test(k));if(bad.length){console.error(\"forbidden or deferred dependency: \"+bad.join(\", \"));process.exit(1)}"'`

## Context

This is the second implementation issue of milestone phase_1_init
(docs/plan.md §phase_1_init). t0 materialized the Chapter 16 placeholder tree;
t2 turns `frontend/` into a real Vite + React 18 + TypeScript 5 application so
that REQ-PLAN-012 ("frontend starts") can be checked and so later milestones
(auth pages, dashboard, forms, charts) have a running harness. The version
targets come from REQ-TECH-001…010 (major-version contracts: React 18, Router
v6, Tailwind 3, TanStack Query 5, Axios 1, Vitest 1, RTL 14, MSW 2, ESLint 8,
Prettier 3); REQ-TECH-081 additionally requires a committed
`package-lock.json`, which ac1 enforces.

Environment reality (recorded by the t0/t1 runs): this working copy lives on a
Windows disk mounted in WSL, and node/npm/npx are Windows binaries. `npx tsx`
and direct node-toolchain calls from WSL fail (esbuild platform mismatch).
Therefore every automatable AC is phrased as a `bash -c` one-liner that
converts the repo-relative `frontend/` path with `wslpath -w` and executes the
toolchain via `cmd.exe /c`. This keeps the commands runnable by Builder and
Verifier in their normal WSL bash environment without manual adaptation.

Contract-first note: `contract_first.require_for` is `[backend, api, database]`
and `allow_natural_for` is `[ui, ux]`. t2 is a frontend *tooling* issue: all
six AC are structurally observable (manifest contents, exit codes, file
presence), so all six got commands; none is a visual/UI-judgment AC.

Granularity note: 6 AC is at the `limits.issue_granularity.max_acs = 6` cap
(`warn_only = true`); the file count exceeds `max_files = 4` by design — a
frontend skeleton necessarily touches a manifest, configs, an entry point, and
a test. Do not inflate the scope further.
