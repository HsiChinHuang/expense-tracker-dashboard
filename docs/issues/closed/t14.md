Contract pins taken from the chapters (the REQs are terse; the chapters are
the tie-break, all re-read during groom):

- **Budget representation (Chapter 7 §7.6.1 `BudgetResponse`) — FROZEN at
  exactly two keys**: `year_month` (string, pattern
  `^[0-9]{4}-[0-9]{2}$`, echoing the path) and `amount` (string, pattern
  `^[0-9]+\.[0-9]{2}$`, e.g. `"2000.00"` — never a JSON number/float,
  REQ-SEC-050). Both required; the response model always emits both, so
  tests assert the key set is EXACTLY `{year_month, amount}` for PUT 200
  and GET 200 (including the absent-month `"0.00"` body).
- **Set body (§7.6.2 `SetBudgetRequest`)**: required `{amount}` where
  `amount` is a STRING matching `^[0-9]+(\.[0-9]{1,2})?$`. No other field
  exists; `year_month` comes from the PATH only.
- **Status codes (§7.6.1..§7.6.3 + Appendix B)**: GET 200/422 (absent month
  is 200 `"0.00"`, NEVER 404); PUT 200/422 (set OR update, always 200 —
  never 201); DELETE 204/404. Malformed path format is 422 on every route
  (W8 pin above). Cross-user DELETE is 404 `NOT_FOUND`, never 403
  (REQ-SEC-031); cross-user GET reads as absent → 200 `"0.00"`
  (REQ-SEC-030 scoping + §7.6.1 behavior note).
- **Error-code split (Appendix B + Chapter 2 §2.5.3, mirrored from t13's
  verifier-accepted split)**: the amount-VALUE cases `"0"`, `"-1"`,
  `"1.234"` (3 decimals), `"10000000000.00"` (over the NUMERIC(12,2)
  capacity `999,999,999.99` — the same capacity tie-break t13 froze and
  the Verifier accepted) and `""` → **422 `INVALID_AMOUNT`, field
  `amount`** (Chapter 2 §2.5.3 lists "Amount is negative → 422
  INVALID_AMOUNT"; the whole VALUE family follows). Structural failures —
  missing `amount` key, unknown extra key, non-string amount — → **422
  `VALIDATION_ERROR`** through the merged `RequestValidationError` handler.
  Chapter 2 §2.5.3's "Duplicate budget for same month → 409
  DUPLICATE_BUDGET" is UNREACHABLE through the API because PUT is upsert
  by contract (§7.6.2, REQ-BE-080); the DB-level UNIQUE is the guard and
  ac1 proves it. The Builder MUST NOT add a 409 path.
- **Service shape (Chapter 6 §6.9.1..§6.9.4)**: `set_budget` selects the
  caller's row for the month; if present → capture old payload, assign new
  amount, `flush`, audit `UPDATE` (old+new), single `commit` + `refresh`;
  else → `add` + `flush`, audit `CREATE` (old NULL), single `commit` +
  `refresh` (REQ-ARCH-023: exactly one commit per request). `get_budget`
  returns the row or `None` (the ROUTER renders the absent case as 200
  `"0.00"` per §7.6.1 — the zero synthesis may live in router or service,
  but the wire body is frozen by ac3). `delete_budget` raises 404
  `NOT_FOUND` (field `null`) when absent, otherwise writes the DELETE
  audit row (old payload, new NULL) inside the same transaction as the
  delete, then commits once (Chapter 6 §6.9.3's order: audit before
  commit). `budget_to_dict` is the byte-pinned two-key payload helper.
  `validate_year_month` (Chapter 6 §6.9.4) may exist in the service, but
  the FROZEN wire behavior for malformed formats is the router/schema-level
  422 pinned in W8 — the service helper must not change it.
- **Decimal discipline (Chapter 5 §5.11.2/§5.11.3, REQ-SEC-050,
  REQ-TECH-022)**: `Numeric(12, 2)` in the model, `decimal.Decimal` in
  Python, string on the wire (mirror t13's `field_serializer` with
  `quantize(Decimal("0.01"))`); SQLite stores `Numeric` as REAL, so reads
  are coerced back to `Decimal` and compared only after
  `quantize(Decimal("0.01"))`. No float may appear in a service function or
  a response body. `year_month` is a plain `str` key end-to-end, never a
  date object (REQ-DB-042, REQ-SEC-051).
- **Constraint names (Chapter 5 §5.6.2/§5.6.3, §5.9) — FROZEN**: unique
  constraint `uq_budgets_user_month` on `(user_id, year_month)`; CHECKs
  `ck_budgets_amount_positive` (`amount > 0`) and
  `ck_budgets_year_month_format`. FK `user_id` → `users.id`
  **`ondelete="CASCADE"`** (Chapter 5 §5.6.2's model and §5.8's FK table
  both say CASCADE; deleting a user removes their budgets — provable with
  a raw `DELETE FROM users` under `create_db_engine`'s enabled FKs).
  **SQLite CHECK emulation — PINNED**: the `~` regex operator does not
  exist in SQLite, so the model module defines
  `YEAR_MONTH_FORMAT_CHECK_SQL = "year_month GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]'"`
  (verified on the pinned SQLite 3.45.1: rejects `2026-1`, `abcd-ef`,
  `20261-3`, `202613`; accepts `2026-10`) and revision 005 imports it
  verbatim — the GLOB is the exact-SQLite emulation of
  `^[0-9]{4}-[0-9]{2}$` (GLOB is anchored and case-sensitive by
  definition). The month-VALUE rule (`01..12`, e.g. `2026-13`) is NOT DB
  enforceable this way and is NOT a DB contract here — it is owned by the
  router/schema pattern (W8: `2026-13` → 422) and, if the Builder keeps
  Chapter 6's `validate_year_month`, by the service. The optional
  `idx_budgets_user_ym` (Chapter 5 §5.6.3) is NOT part of the contract —
  the named UNIQUE constraint is sufficient; adding it is allowed but
  unverified.

## Constraints

- `year_month` is a string key, never a date object, in service and schema
  layers (REQ-DB-042, REQ-SEC-051).
- `GET` absence → 200 `"0.00"` is intentional contract behavior; do not
  "fix" it to 404. Malformed format → 422 (W8) is equally intentional; the
  two cases must never collapse into one branch.
- Amounts: `decimal.Decimal` end-to-end; NEVER float in service or schema;
  JSON serialization is the 2-dp string form via a `field_serializer`
  mirroring t13 (REQ-SEC-050, Chapter 5 §5.11.2/§5.11.3). AMOUNT_MAX is
  the `999999999.99` NUMERIC(12,2) capacity tie-break t13 froze and the
  Verifier accepted.
- One session per request; the service commits exactly once; the audit
  write is inside that transaction via t12's `write_audit_log`
  (REQ-ARCH-023/078). The service imports the writer UNQUALIFIED
  (`from app.audit.logger import write_audit_log`) — that module-level
  name is the pinned W7 seam ac5 monkeypatches.
- Upsert is SELECT-then-UPDATE-or-INSERT in one transaction (Chapter 6
  §6.9.1); the UNIQUE constraint is the race guard. FORBIDDEN: retry
  loops, `ON CONFLICT` SQL, or any concurrency machinery (W9;
  REQ-PROD-035 is phase_5).
- Alembic: revision `005` only (`down_revision = "004"`); constraint names
  are the frozen Chapter 5 §5.6 names; the three CHECK/constraint SQL
  strings live in `app/models/budget.py` and revision 005 imports them; no
  data step.
- Test layout: COPY the t13 harnesses (no conftest.py, no cross-test-module
  imports); cross-user tests register TWO real users through the real
  register endpoint. Test module names follow the merged t13 precedent
  (`test_budget_api.py` singular, matching `test_expense_api.py`; Appendix B
  §28's `test_budgets_api.py` naming was already deviated from at t13).
- **max_files=4 exceeded** (model + migration + schemas + service + router +
  main.py wiring + 4 test modules ≈ 9 paths) and **max_diff_lines=300 very
  likely exceeded**: `limits.issue_granularity.warn_only = true`,
  pre-declared per the t8/t9/t11/t13 W14 precedent — the vertical is NOT
  split.
- Deleting a user cascades to budgets (DB-level FK CASCADE, proved in ac1);
  adding the optional `User.budgets` ORM relationship is Builder's choice
  and is NOT part of the contract.
